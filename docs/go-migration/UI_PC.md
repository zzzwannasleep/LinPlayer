| 来源 | 权重 | 说明 |

## 1. 设计系统

### 1.1 色彩

**单一色彩真相源。** 现有 `ui/shared/tokens.css` 是被用户调过多轮的成品,
Avalonia 侧建一份 `Tokens.axaml` 的 `ResourceDictionary`,**值逐个照抄**。

设计语言:**影院沉浸式 —— 分层表面 + 极细发丝线 + 三级墨色 + 单一强调蓝**。
两套主题:沉浸深色 + **米黄护眼暖纸**(浅色不是纯白,墨色带暖偏不是纯黑)。

| token | 深色(默认) | 浅色 | 用途 |
|---|---|---|---|
| `bg` | `#0c0f14` | `#f1ece2` | 页面底 |
| `bg-tint` | `91,141,239` | `63,115,214` | 顶部氛围雾的 rgb |
| `panel` | `#141922` | `#fbf8f1` | 卡片 / 面板 |
| `panel-alt` / `panel-2` | `#1b212c` | `#f5f0e6` | 次级面板、悬停底 |
| `line` | `#252c38` | `#e4dccc` | 发丝线 |
| `line-strong` | `#323b4a` | `#d6ccb6` | 强分隔、滚动条滑块 |
| `ink` | `#e8ebf1` | `#2a2622` | 主文字 |
| `ink-2` | `#9aa4b4` | `#6e6559` | 次要文字 |
| `ink-3` | `#6b7688` | `#9c9284` | 三级文字 / 占位 |
| `accent` | `#5b8def` | `#3f73d6` | 强调 |
| `accent-ink` | `#08101f` | `#ffffff` | 强调底上的文字 |
| `accent-soft` | `rgba(91,141,239,.16)` | `rgba(63,115,214,.13)` | 强调底(选中 / 标签) |
| `warn` | `#e0a95b` | `#c98a2e` | 警告 |
| `good` | `#54c08a` | `#3e9e6e` | 成功 / 已看 |
| `danger` | `#e5726b` | `#c7554e` | 危险 / 删除 |
| `scrim` | `rgba(12,15,20,.9)` | `rgba(241,236,226,.9)` | 遮罩 |
| `chip-bg` | `rgba(20,25,34,.55)` | `rgba(255,255,255,.74)` | 玻璃底小控件 |
| `ph` / `ph-2` | `#1e2530` / `#161b24` | `#eae2d2` / `#f2ebdd` | 骨架占位 |
| `card-shadow` | `0 18px 40px -20px rgba(0,0,0,.7)` | `0 18px 38px -22px rgba(107,93,63,.32)` | 卡片投影 |

#### 三条不许破的色彩约束

1. **玻璃底小控件必须用 `chip-bg` token,不许写死 rgba。**
   悬浮小按钮、标签、详情返回键这些以前写死 `rgba(20,25,34,.55)`,
   浅色主题下就是**深底深字**看不见 —— 用户 2026-07-16 报过。
2. **`good` 不是"绿色"是"已看"。** 已看勾、成功态共用一个 token,别为了好看各挑一个绿。
3. **强调色只有一个。** 不引入第二强调色。需要区分层级时用 `accent-soft` 与不同墨阶。

#### 主题切换

- 三态:**跟随系统 / 强制深色 / 强制浅色**,默认跟随系统。
- 切换**不许闪白**:Avalonia 换 `ResourceDictionary` 时先换资源再刷新,
  不要走"卸载窗口重建"。【待验证】Avalonia 11 的 `ThemeVariant` 切换是否有可见闪烁。
- 快捷键 `Alt+T` 直接切深浅(跳过"跟随系统")。

### 1.2 排版

| 项 | 值 |
|---|---|
| 无衬线 | `Segoe UI` → `Microsoft YaHei UI` → `PingFang SC` → `Noto Sans CJK` → 系统 |
| 等宽 | `Cascadia Code` → `Consolas` → `SF Mono` → 系统等宽 |
| 正文 | 13 px / 1.55 |
| 次要 | 12 px |
| 标注 | 11.5 px |
| 标题栏应用名 | 12.5 px / `weight 650` / `letter-spacing .01em` |
| 区块标题 | 15 px / `weight 650` |
| 页面大标题 | 22 px / `weight 700` |
| Hero 标题 | 34 px / `weight 750` |

- **中文不加 `letter-spacing`**(除标题栏应用名这一处)。中文字距拉开只会显得松散。
- 数字与时长用等宽字体的 `tabular-nums`,否则进度时间每秒都在抖。
- **抗锯齿开 `antialiased`**,不要 `subpixel` —— 深色底上 subpixel 会出彩边。

### 1.3 间距 · 圆角 · 线 · 阴影

| 项 | 值 |
|---|---|
| 间距阶 | `4 / 6 / 8 / 10 / 12 / 14 / 18 / 24 / 32 / 48` |
| 圆角 | `r-sm 8` · `r-md 12` · `r-lg 16` · `r-xl 22` · 药丸 `999` |
| 发丝线 | **1 物理像素**,颜色 `line`。高 DPI 下不许被缩放成 1.5px 的糊线 |
| 阴影 | 只有 `card-shadow` 一档。**不做多级 elevation** —— 层级靠表面色阶表达,不靠投影堆叠 |

> **为什么阴影只有一档:** 深色沉浸底上,投影几乎看不见,堆多级只会让边缘发脏。
> 层次由 `bg → panel → panel-alt` 三阶表面色 + 发丝线表达。

### 1.4 图标

- **单一线性图标族,`stroke-width 1.75`,`24×24` 网格,圆头圆角。**
- 图标颜色跟随文字墨阶(`ink` / `ink-2` / `ink-3`),**不给图标单独配色**。
- 现有 `ui/desktop/app/icons.tsx` 是已收敛过的集合,迁移时逐个转成 Avalonia
  `PathGeometry` 资源,**不要引入图标字体**(字体缺字时是豆腐块,而且不跟墨阶)。

### 1.5 滚动条

沉浸式细滚动条,**不用系统粗条**:

| 项 | 值 |
|---|---|
| 宽 | 10 px |
| 滑块 | `line-strong`,圆角 `999`,内缩 3 px(靠透明边框实现) |
| 悬停滑块 | `ink-3` |
| 轨道 | 透明 |

### 1.6 两条底层约束(破了就是黑屏或错位)

1. **窗口根必须透明。** 播放时整个 UI 外壳隐藏,露出底下的视频层;
   不透明的设计底色**只画在 `.app-surface` 这一层**(非播放屏)。
   播放屏什么都不画,只叠控制条渐变。
   > 新架构下视频在窗口内合成(`SPEC.md` §7.3),这条的形式会变,但**"播放屏不画不透明底"
   > 这个约束仍然成立** —— 【待验证】方案 B 落地后确认视频层的合成顺序。
2. **正文封顶居中 1560 px。**【用户定,实测】超宽屏(2560+)不封顶的话表单行会拉到 2000 px、
   设置项的开关甩到屏幕最右、中间全空。
   语义:这是**含 18 px 左右水槽的外框宽**,水槽在框内 ——
   顶栏和正文都按这个宽度封顶居中,墨迹才落在同一条竖线上。

## 2. 动效规范

> 总纲:**动效负责解释空间关系,不负责表演。**
> 本项目有过一次教训 —— 用户 2026-07-15 当面纠正:「其实不秒加载并不是你的动画问题」。
> 当时我量到「入场 380ms + 阶梯 288ms = 最后一张卡 668ms」就把动画砍了,那是拿掉表象;
> 真因是加载结构(`Promise.all` 屏障 + 串行 await),那是**秒级**的。
> **所以:动效可以做得讲究,但它永远不是性能问题的答案。**

### 2.1 token

| token | 值 | 用在哪 |
|---|---|---|
| `dur-fast` | **140 ms** | 悬停、按下、开关、图标态变化 |
| `dur-med` | **240 ms** | 浮层进出、侧栏折叠、面板切换 |
| `dur-slow` | **380 ms** | 页面转场、大面积位移 |
| `ease` | `cubic-bezier(.22,.61,.36,1)` | 默认。快出慢收 |
| `ease-emph` | `cubic-bezier(.2,.8,.2,1)` | 强调进场(浮层、Hero) |

**只有这三档时长。** 需要"更快一点"就用 `dur-fast`,不许现场发明 90ms。

### 2.2 转场目录

| 场景 | 做法 | 时长 / 缓动 |
|---|---|---|
| 页面切换 | **只淡入,不位移** —— 见 §2.3 第 1 条 | `dur-slow` / `ease` |
| 侧栏折叠 | 宽度 212↔72 | `dur-med` / `ease` |
| 下拉 / 浮层 / 右键菜单 | 淡入 + 沿锚点方向位移 6 px | `dur-med` / `ease-emph` |
| 对话框 | 遮罩淡入 + 卡片 `scale .96→1` | `dur-med` / `ease-emph` |
| Toast | 从出现方向滑入 12 px + 淡入 | `dur-med` / `ease-emph` |
| 卡片悬停 | 上抬 2 px + 阴影加深 + 封面 `scale 1.03` | `dur-fast` / `ease` |
| 按下反馈 | `scale .98` | `dur-fast` |
| 封面到位 | 图片解码完成后淡入(骨架淡出) | `dur-med` |
| 骨架 → 内容 | 骨架**原地淡出**,内容淡入,**不做尺寸动画** | `dur-med` |
| 进度条拖动 | 跟手,**零动画**(见 §2.3 第 3 条) | — |
| OSD 显隐 | 淡入淡出 | `dur-med` |
| 详情页 Hero 背景换图 | 交叉淡入 | `dur-slow` |

**页面滚动是平滑滚动。**【用户定】2026-07-16「页面浏览滑动有点卡卡的 加一下线性速度」——
翻页 / 锚点 / 键盘滚动走缓动,**不引任何惯性库**(鼠标滚轮本身交给系统)。

### 2.3 三条禁令

**1. 页面入场动画不许带位移(`transform` / `RenderTransform`)。**

Web 上的具体原因:带 `transform` 关键帧的元素会成为 `position:fixed` 的**包含块**,
而且 Chromium 在动画播完后依然保持。后果是这一页里所有浮层不再相对视口 ——
右键菜单飘到隔壁条目上,toast 的居中也不再是屏幕中间。
【实测】headless Edge,fixed 元素 `left:100px`,侧栏 200px:
无动画 → 100 ✓ / 只有 opacity → 100 ✓ / 含 transform + `both` → **300 ✗** /
含 transform + `backwards` → **300 ✗**。

**Avalonia 上这个具体机制不存在**(没有 `position:fixed`),但等价风险是
`RenderTransform` 影响 `Popup` / `Flyout` 的定位基准。
**【待验证】** SPIKE 里必须验一次:给页面根挂 `RenderTransform` 动画,
断言右键菜单与 toast 的屏幕坐标不变。**验不过就沿用"只淡入"这条。**

**2. 列表项不挂阶梯延迟。**
入场 380 ms + 300 ms 阶梯 = 最后一张卡 **680 ms 才出现**,而且延迟期间完全不可见。
内容出现**不能被动效挡着**。区块级可以有入场,**项级不许**。

**3. 跟手的东西每帧绕过声明式层直接写变换。**
拖拽、进度条、手势:跟手期间走状态更新 = 每帧一次重组。
**跟手期间直接改 `RenderTransform`,松手后把最终值交回状态。**
「这不是猜的」—— 桌面端进度条就是这么栽的。

### 2.4 减少动态

跟随系统的"减少动画"设置(Windows:`SystemParametersInfo SPI_GETCLIENTAREAANIMATION`;
Linux:`gtk-enable-animations`)。开启时:

- 所有时长压到 ≈ 0(保留状态切换,去掉过程)
- 跑马灯不滚,改成两行换行显示
- 交叉淡入变成直接替换

### 3.1 外壳骨架

```
┌────────────────────────────────────────────────────────────┐
│ 自绘标题栏  36px   [logo 名称]      [拖拽区]      [— □ ×]  │
├──────────┬─────────────────────────────────────────────────┤

│ 212px    │  ┌───────────────────────────────────────────┐  │
│ (折叠 72)│  │  正文  封顶 1560px 居中                     │  │
│          │  │                                            │  │
│ 服务器    │  │                                            │  │
│ 切换器    │  └───────────────────────────────────────────┘  │
│ 导航项    │                                                 │
└──────────┴─────────────────────────────────────────────────┘
```

| 项 | 值 |
|---|---|
| 标题栏高 | 36 px |
| 侧栏宽 | 212 px【用户定】(草稿原为 186,2026-07-16「侧边栏有点小了 可以大一点」) |
| 侧栏折叠宽 | 72 px |
| 正文封顶 | 1560 px |
| 内容区左右水槽 | 18 px(在封顶宽之内) |
| 窗口最小尺寸 | **1024 × 640** |

### 3.2 断点与网格

**不做移动式断点。** PC 只有一条自适应规则:**网格按最小卡宽自动填列**,
外加 1560 px 封顶。这样从 1024 到 4K 都成立,不需要维护断点表。

| 网格 | 最小卡宽 | 卡片比例 |
|---|---|---|
| 海报网格(剧 / 电影 / 收藏 / 搜索结果) | **150 px** | `2 / 3` |
| 横版网格(继续观看 / 分集 / 媒体库卡) | **240 px** | `16 / 9` |
| 服务器图标库 | 96 px | `1 / 1` |
| 详情页 Hero | 整宽 | `26 / 7` |
| 主从两栏(设置 / 添加服务器) | 左栏 **214 px** 固定,右 `1fr` | — |

两条踩过的坑,写进契约:

- **`aspect-ratio` 与 `max-height` 不许并存** —— 二者并存会把宽度反锁(详情页 Hero 栽过)。
  Avalonia 侧等价:同时设 `Viewbox` 比例和 `MaxHeight`。
- **卡宽不定的容器里,`auto-fill` 只出 1 列。** 容器必须有确定的可用宽度;
  `flex:1` 只对**直接子元素**生效,挂错一层就是"每行一张图 / 图巨大"。

### 3.3 窗口行为

| 项 | 规定 |
|---|---|
| 装饰 | **无边框 + 自绘标题栏**(Avalonia `ExtendClientAreaToDecorationsHint`) |
| 拖拽 | 标题栏中段是拖拽区;**双击 = 最大化 / 还原**,右键 = 系统菜单 |
| 最大化 | 见下方"溢出"一条 |
| 全屏 | `F11`(主窗)/ `F`(播放窗)。全屏时标题栏整条撤掉 |
| 窗口态 | **必须回读,不许自己记账**(见下) |
| 位置记忆 | 关窗时记 `x/y/w/h/maximized` + **所在显示器的标识**;下次在同一显示器还原,该显示器不在了就落回主显示器居中 |
| DPI | 支持 per-monitor DPI 感知。跨屏拖动要重算,**发丝线仍是 1 物理像素** |
| 关闭 | 主窗关闭 = 退出(见 §3.5) |

#### 【坑】Windows 上的四条窗口几何陷阱

**四条全部只有挂真 exe 才量得出来**,读代码和跑单测一条都发现不了。
完整论证见 [`SPEC.md`](SPEC.md) §16.5,这里是做的时候要照办的部分:

| # | 坑 | 规则 |
|---|---|---|
| 1 | **设位置的接口吃逻辑像素,读位置 / 尺寸的接口返回物理像素** | 几何计算**全程用物理像素**,只在最后转换。把单位写进变量名 —— 混用的表现是 150% 缩放下位置整体偏 1.5 倍 |
| 2 | **无边框窗外框比可见区域每边宽出一圈**(实测 150% 下 11 px),而且**建之前量不到** | **先隐身建窗 → 拿真实外框尺寸 → 再摆位置 → 才 show** |
| 3 | 最小化窗口的位置是哨兵值 `(-32000,-32000)` | 任何"相对另一个窗口定位"的计算都要先滤掉它,否则新窗口被扔到屏幕外 |
| 4 | **最大化态下直接切全屏,标志位翻了但几何一动不动** | 见下方【契约】 |

#### 【契约】进全屏之前必须先退出最大化

用户报过**两次**:「窗口最大化之后,点全屏按钮无效,依旧还是最大化」。

挂真 exe 量出来的根因:最大化态下切全屏,标志位会变成 true 而**客户区一个像素都不动**
(实测 2560×1599 原样)—— 标题栏还在、画面还让着标题栏那条,用户看到的就是"按钮没用"。

```
进全屏:记住"进来前是不是最大化" → 先退最大化 → 再进全屏
退全屏:退出全屏 → 若之前是最大化,还原成最大化
```

**全屏调用必须只有一个出口**,并有契约测试钉住(`SPEC.md` §16.5 ④)。

#### 【状态未确认】无边框窗最大化溢出 8 px

无边框窗最大化时系统把窗口四周各外扩约 8 px,**自绘的窗口控制按钮被顶出屏幕**,
表现是"最大化后控制栏没了"。

**别照抄旧结论 —— 先看清现状:**

- 根治方案(在系统的"取最大化尺寸"消息里把尺寸钉到显示器**工作区**;
  只钉最大尺寸与位置,**不要钉最大跟踪尺寸**,钉了会卡住原生全屏铺满整屏)
  **写在已经被删掉的旧运行时里**,当前仓库中不存在
- 当前版**没有任何补偿代码**;播放窗是绕开的 —— **几何照抄主窗、不真的 maximize**
- 所以「Avalonia 的 `ExtendClientAreaToDecorationsHint` 下这个问题还在不在」——**未确认**

**SPIKE 里实测:最大化后量右上角按钮是否完整可见。** 两种结论都要写下来。

> 顺带一个自检工具本身的陷阱:**截图进程默认 DPI 不感知**,屏幕坐标会被虚拟化,
> 截出来内容偏移、按钮"消失"**是假象**。自检工具必须先声明 per-monitor DPI 感知再截图,
> 否则你在追一个不存在的 bug。

#### 【用户定】窗口态必须回读

全屏 / 最大化的图标状态**每次都从窗口回读**。
用户会从系统侧改窗口态(双击标题栏、`Win+↑`、热键),只在点击时翻标志位的写法迟早对不上。

配套:播放中不渲染常规标题栏时,**必须自绘一组窗口控制**(最小化 / 窗口化 / 全屏各有各的按钮)。
用户 2026-07-16 报「点了全屏就一直全屏,根本没有其他操作」——
根因不是退不出去,是**界面上看不出来还能退**。

### 3.4 播放窗

**播放页是独立窗口,不是主窗里的一页。**

| 项 | 规定 |
|---|---|
| 标题栏 | **不全屏时常驻标题栏**【用户定】——「单开的播放页要有标题栏,不然拖不动」 |
| 内容让位 | 视频是**窗口内的一个控件**(`OpenGlControlBase`,`SPEC.md` §7.2 通道 B),布局照常排,**不再需要"两个几何入口都要减 36px"那套** |
| 全屏 | 撤标题栏,视频铺满 |
| `Alt+F4` | **必须拦截** —— 直接关掉会留下正在播放的核心层状态 |
| 关闭 | 停播 → 落进度 → 关窗。**先落库再退**,并有 3 秒兜底 |
| 与主窗关系 | 同进程,直接共享对象。`player_take_pending` 这类"绕道核心层传参"的命令**不再需要** |
| 视频通道 | 主窗与播放窗**共用同一条 GL 通道** —— 一个进程只能有一条(`SPEC.md` §7.2 通道 B 约束 4)。实测:连开两条会卡死 |
| OSD | 就是普通的 Avalonia 控件叠在视频控件上。**没有 airspace 问题,也不碰 mpv 的 Lua OSD** |

### 3.5 退出

**「关掉程序还留进程」在 Rust 版是真实故障,根因不是 mpv 也不是子进程,是 exe 自己** ——
播放窗被藏起来而不销毁,窗口系统永远等不到"最后一个窗口关闭"。

新架构的退出序列:

```
用户关主窗
  → 若在播:先让播放窗落库(进度 / 观看记录),等它完成或 3 秒超时
  → lp_gl_uninit()   ★ 必须在销毁 GL 上下文之前,阻塞返回(SPEC §7.2)
  → 销毁所有窗口(藏起来的也要销毁)
  → lp_shutdown()  阻塞直到核心层落盘完成
  → 事件线程收到 EOF 退出
  → 进程退出
```

**验收只能在真 exe 上做** —— 关窗后查进程表必须干净。IDE 里跑不算。

> 顺序里 `lp_gl_uninit()` 排在销毁窗口**之前**,和通道 A 的 surface 解绑同一个理由:
> 上下文没了而核心层还在往里画 = use-after-free。

### 3.6 双端窗口差异

本章的规格两端共用,但**落法不同**,而且有几处两端都还没有:

| 项 | Windows | Linux |
|---|---|---|
| 无边框最大化溢出 | 溢出约 8 px。**当前版无补偿代码,状态未确认**(§3.3) | **各 WM 行为不同**,没有统一机制。【待验证】 |
| 窗口装饰 | 自绘(CSD) | CSD / SSD 由 WM 决定;**部分 WM 会强行加自己的边框** 【待验证】 |
| DPI | per-monitor,跨屏拖动要重算 | X11 全局缩放 / Wayland 分数缩放,**两套机制** 【待验证】 |
| 位置记忆 | 可靠 | **Wayland 上客户端定不了自己的绝对位置**(见 `SPEC.md` §15.2) |
| 减少动画的系统设置 | 系统参数 | `gtk-enable-animations` |
| 托盘 | 通知区 | 桌面环境**可能根本没有**。托盘是增强不是必需路径 |
| 屏幕常亮 | 系统 API | D-Bus 抑制,**接口可能不存在 → 静默降级**。两端都**不许依赖 mpv 的 `stop-screensaver`** —— render API 模式下 mpv 没有自己的窗口(`SPEC.md` §15.5) |
| 系统媒体控制 | SMTC | **MPRIS**(优先级更高 —— 它把媒体键 / 锁屏 / 通知中心一次全接上) |
| 文件选择器的后缀过滤 | 正常 | **选"程序"时不许加后缀过滤**,否则列表是空的 |

> **位置记忆那条要特别小心。** 如果 SPIKE-1 定的是"跟随会话"(即支持 Wayland),
> 那么 §3.3 的"记 x/y 并还原"在 Wayland 下**做不到**,只能记尺寸与最大化态。
> 这不是可以糊过去的差异 —— 要么明确降级并说明,要么强制 X11。

## 5. 交互规范

### 5.1 快捷键

**架构是"命令注册 + 一条全局监听",不是各处各挂一个键盘事件。**

理由有二:① 各挂各的会互相打架(曾出现"播放页按 F5 也会刷新底下那一页");
② 各挂各的意味着**没有任何地方能列出全部快捷键**,更不可能让用户改键。

```
按键 → combo 字符串 → 命令 id → 谁注册了谁执行
```

改键只改这张表,设置页照着表渲染就是完整且诚实的快捷键列表。
**combo 口径:全小写,修饰键固定顺序 `ctrl+alt+shift+meta`。**

#### 全局

| 命令 | 键 | 生效范围 |
|---|---|---|
| 搜索 | `Ctrl+K` | 主界面 |
| 刷新当前页 | `F5` | 主界面 |
| 返回上一层 | `Alt+←` | 主界面 |
| 折叠 / 展开侧栏 | `Alt+S` | 主界面 |
| 切换深色 / 浅色 | `Alt+T` | 主界面 |
| **按键提示** | `;` | 任何时候 |
| 快捷键一览 | `Shift+?` | 任何时候 |

#### 页面切换

`Alt+1`…`Alt+9` = 首页 / 媒体库 / 收藏 / 下载 / 排行榜 / 追剧日历 / 服务器 / 插件 / 设置

#### 播放

| 命令 | 键 | | 命令 | 键 |
|---|---|---|---|---|
| 播放 / 暂停 | `空格` `K` | | 上一集 / 下一集 | `P` / `N` |
| 快退 / 快进 10 s | `←` / `→` | | 倍速 ∓0.25 | `[` / `]` |
| 快退 / 快进 60 s | `Shift+←` / `Shift+→` | | 倍速归 1.0 | `退格` |
| 音量 ± | `↑` / `↓` | | 截图 | `S` |
| 静音 | `M` | | 复制当前时间 | `Ctrl+Shift+C` |
| 全屏 | `F` | | 弹幕开 / 关 | `D` |
| 关闭面板 / 退出播放 | `Esc` | | | |

#### 播放页面板

`E` 选集 · `A` 音轨 · `C` 字幕 · `Shift+D` 弹幕 · `U` 超分 · `L` 线路 · `V` 版本 · `R` 倍速 · `O` 更多

#### 鼠标手势(固定,不可改键)

| 手势 | 动作 |
|---|---|
| 长按右键 | 临时 2× 快进,松开还原 |
| 双击画面 | 全屏切换 |
| 滚轮 | 音量 ±5 |
| 中键 | 静音 |

> 手势要**列在设置页的快捷键表里**(让用户知道有这回事),但不参与录键 ——
> 录键器只收键盘事件。做法:用 `mouse:*` 前缀的伪 combo,键盘永远产不出这个前缀,
> 所以既不会被误触发也不会和真键位撞车,**不用给冲突检测开特例**。

#### 冲突

同一范围里两条撞了,**后面那条永远轮不到,而且不报错**。
设置页必须把冲突**标红**,并且录键时当场提示"该键已被 X 占用"。

### 5.2 按键提示层(`;`)

**「所有能点的按钮都能用快捷键」这条,靠两层共同满足:**

1. §5.1 的具名命令 —— 高频动作(导航 / 播放 / 面板),可改键;
2. **按键提示层** —— 按 `;` 后,给当前屏幕上**每一个**可点元素现场发一个字母标签,
   输字母即点击。

第二层是关键:**页面以后新增按钮也自动覆盖**,不需要有人记得回来往命令表里补一条。

规格:

- 标签按元素在屏幕上的**阅读顺序**分配(从上到下、从左到右),不是 DOM 顺序
- 可点元素 > 26 个时用两字母
- 标签贴在元素左上角外侧 2 px,`accent` 底 + `accent-ink` 字,11 px 等宽
- `Esc` 或再按一次 `;` 退出;输错字母直接退出(不惩罚)
- **浮层打开时只标浮层内部**的元素(否则用户会点到被遮住的东西)

### 5.3 右键菜单

- **覆盖全部网格卡片与列表行**,不是只有媒体库。
- 菜单在光标处弹出;**贴边时向内翻转**,不许被窗口裁掉。
- 分组用发丝线分隔;危险项(删除 / 移除)放最后一组并用 `danger` 色。
- **打开菜单的背板不能盖住触发它的那一层。**
  > 教训:顶栏下拉的关闭背板盖住了整条顶栏(层叠上下文问题),表现是"顶栏下拉点不动"。
  > 背板要放在**它所属浮层的内部**,不要挂到根上。
- 菜单项与卡片悬停动作**必须是同一份定义**(现有 `cardActions` 的做法),
  否则两处会长歪 —— 悬停有"标记已看"而右键没有,这种不一致用户一定会遇到。

### 5.4 导航栈、返回与滚动恢复

| 项 | 规定 |
|---|---|
| 栈 | 页面栈,`Alt+←` 出栈。**侧栏切换是"换根"不是"入栈"** |
| 滚动恢复 | 出栈回到上一页时**必须恢复滚动位置**,并且要恢复到**内容已就位之后**的位置 |
| 列表缓存 | 返回时**不许重新拉取**。列表结果有缓存,靠 `data.invalidate` 事件失效(`SPEC.md` §5.8) |
| 深链 | 从 `linplayer://` 进入的页面,栈里要有一个可回退的根(不能一按返回就退出) |

> 滚动恢复漏了的表现:从详情页返回媒体库,回到了顶部,用户要重新滚很久。
> 这在 TV 上是致命的(返回键是主交互),在 PC 上只是烦 —— 但两端应当一致。

### 5.5 焦点与键盘导航

PC 端不做 TV 那样的空间导航,但**必须键盘可达**:

- `Tab` / `Shift+Tab` 走标准焦点顺序;网格内用方向键在卡片间移动。
- **焦点环只在键盘导航时出现**(鼠标点击不出)。落法:跟踪最后一次输入是键盘还是指针。
- 浮层 / 对话框打开时**焦点陷阱**:`Tab` 在浮层内循环,`Esc` 关闭并把焦点还给触发元素。
- **焦点项不许贴在裁剪边上** —— 滚动容器要为焦点环留出至少 4 px 的内边距,
  否则焦点环会被裁掉一半,用户看不出焦点在哪。

### 5.6 悬停提示、拖放、多选

| 项 | 规定 |
|---|---|
| **悬停提示** | 延迟 **500 ms** 出现,移开立即消失;同一组内连续悬停**不重新计时**。位置贴元素下方,贴边时翻转。**只放补充信息** —— 图标按钮的名字、状态点的含义;不许放操作说明 |
| **拖放排序** | 服务器卡、线路行。拖动中原位留一个占位槽;**筛选状态下必须回原表查真实下标**(§7.5) |
| **拖入文件** | 拖一个视频文件进主窗 = 走本地播放。**必须有越狱闸**(只接受视频扩展名,路径交核心层校验) |
| **多选** | **不做。**【决定】媒体库的批量操作由右键菜单里的"选择模式"承担,不引入 `Ctrl` / `Shift` 多选 —— 引入它意味着每个网格都要重做键盘与焦点语义,而实际需求只有"批量标已看"一件事 |

> 拖入文件这条是**新增能力**,老版本没有(老版本的拖放只用在服务器卡排序上)。
> 它很便宜且符合桌面直觉,但**必须走和"选择文件夹"同一条越狱闸**,不能因为
> "是用户自己拖进来的"就跳过校验。

## 6. 反馈层

### 6.1 Toast

| 项 | 规定 |
|---|---|
| 位置(主界面) | **中部偏下**【用户定,三端统一】 |
| 位置(播放页) | **顶部居中**【用户定】—— 底部被控制条占着 |
| 时长 | 普通 3 s,错误 5 s,带动作的不自动消失 |
| 层级 | 最上层,**在对话框之上**(对话框里的操作也要能给反馈) |
| 堆叠 | 最多 3 条,超出的替换最旧的 |
| 内容 | 一行。需要多行说明的**不是 toast,是对话框** |

**Toast 不许承载唯一的重要信息。** 用户可能正好没看屏幕。
失败必须同时体现在**界面状态**上(那一行变红 / 那个开关弹回去)。

### 6.2 对话框与确认策略

**【用户定】设置页全页零二次确认 —— 改完即生效,没有保存按钮。**

这是已经拍过板的产品口径,新版本照做。配套的两条硬要求:

1. **越界值让核心层拒绝,不要在 UI 上夹紧。**
   UI 夹紧的话用户输 999 会静默变成 32,他以为设成 999 了。
   正确做法:原样发给核心层,核心层回 `E_INVALID`,UI 显示错误并**回滚到旧值**。
2. **失败必须回滚。** 开关立即翻过去(乐观更新)是对的,但命令失败时必须翻回来 + 报错。
   不回滚的表现是"开关是开的但功能没生效",而这是本项目最难查的一类 bug。

需要确认对话框的**只有三类**:

| 类 | 例子 |
|---|---|
| 不可逆的删除 | 删除服务器 / 卸载插件 / 清空观看记录 |
| 影响他人的动作 | 服务器管理(扫描媒体库 / 刷新元数据) |
| 会丢数据的导入 | 导入配置(覆盖现有) |

**其余一律不确认。** 加二次确认是最便宜的"负责"姿势,也是最伤手感的。

### 6.3 错误码 → UI 行为映射

`SPEC.md` §5.4 定义了错误码,这里定义 PC 端**必须**怎么响应:

| code | PC 端行为 |
|---|---|
| `E_AUTH` | 弹重新登录对话框(**对扫码型源要给扫码,不是账密框**);不要只弹 toast |
| `E_NETWORK` | 行内错误态 + 重试按钮。**不弹 toast**(网络抖动时会刷屏) |
| `E_UPSTREAM` | Toast 显示 `msg`,详情写日志 |
| `E_UNSUPPORTED` | **静默降级,不显示任何错误。** 隐藏该入口 |
| `E_NOTFOUND` | 空态 |
| `E_PERMISSION` | 插件权限对话框 |
| `E_INVALID` | 行内错误 + 回滚(见 §6.2) |
| `E_SHUTDOWN` | 忽略 |
| `E_INTERNAL` | Toast「出错了」+ 一个"复制诊断信息"的动作 |

> `E_UNSUPPORTED` 单列是有原因的:媒体源有一批"默认不支持"的可选能力,
> UI 探测它们时收到的不是错误而是信息。混在一起的表现是**"进网盘就弹一个红色报错"**。

### 6.4 加载、骨架与空态

**三条硬规矩:**

1. **骨架先出,内容各自到位。**【用户定】2026-07-16「先加载骨架出来,名字这种文字先出来,
   图片有加载动画看起来不会这么卡」。
2. **页面不持有一个全局 loading。** 每个区块自己一个 `Loading / Loaded / Failed`。
   一个区块失败不许让整页变成错误页。
3. **失败提示必须挂在加载分支里面。**
   > 教训:设置页读取失败的提示挂在了加载分支外面,结果那个 toast 根本没被挂载 ——
   > 用户只看到"读取中…"转到天荒地老,真正的原因被界面吞了。

空态文案必须区分三种情况,**不许都写"暂无内容"**:

| 情况 | 文案方向 |
|---|---|
| 真的没有 | 「这里还没有内容」 |
| 没配置 | 「还没有添加服务器」+ 一个跳转按钮 |
| 被过滤掉了 | 「当前筛选没有结果」+ 一个清除筛选按钮 |

### 6.5 更新提示

自更新的机制在 `SPEC.md` §14.9,这里只定 UI:

| 阶段 | UI |
|---|---|
| 发现新版本 | **不打断。** 侧栏"设置"上挂一个小圆点 + 设置页顶部一条横幅 |
| 用户点了更新 | 设置页内联进度条(不是模态框),**可以继续用 App** |
| 下载完成 | 一条带动作的 toast:「重启以完成更新」/「稍后」 |
| 失败 | 内联错误 + 重试。**回到旧版正常用**,不许留半装状态 |

- **不做强制更新弹窗。** 用户正在看片时弹一个"必须更新"是最招人烦的一件事。
- 更新说明(release notes)在设置页展开看,**不塞进 toast**。

## 7. 页面规格

> 每页四行契约:**区块 / 加载 / 失败 / 空态**,外加「不许退回去的决定」。
> 每条决定背后的完整来龙去脉见 [`knowledge/UI_LESSONS.md`](knowledge/UI_LESSONS.md) §2,
> 本节只写**做的时候必须照办的那部分**。
>
> **通用规则,不在每页重复:** ① 骨架先出、各块各自渲染,不设屏障 ② 一个区块失败不整页报错
> ③ 列表结果有缓存,靠 `data.invalidate` 失效 ④ 所有网格卡有右键菜单。

### 7.1 首页

| | |
|---|---|
| 区块 | ① Hero(随机推荐 5 条,只取有剧照的,大幅剧照 + **片名艺术字 logo**)② 继续观看(12)③ 接下来看(20)④ 媒体库入口轨 ⑤ **每个媒体库一条「最新」轨** ⑥ 合集 |
| 加载 | 各块并发,媒体库最新轨**并发不串行**(八个库串行 = 八次往返) |
| 失败 | 各块各自 catch。**只有媒体库列表是地基**,它挂了才算真错误并显示整页错误条 |
| 空态 | Hero 未到 → 骨架块占位;媒体库列表未到 → 先出两条最新轨骨架(否则首屏下半是空的) |

- **艺术字 logo 取不到 → 回落成文字标题,并隐藏下面那行标题**(否则重复)。
  失败**按条目 id 记,不是一个布尔** —— 否则翻到下一张 Hero 还顶着上一张的失败态。
- **屏蔽条目后整页重拉,不在 UI 逐个过滤。** 首页手里有六份互不相干的列表副本,
  挨个过滤 = 把核心层的规则在 UI 再抄一遍,抄错还不报错。
- **媒体库入口卡也要能右键屏蔽整个库**(库卡没有已看 / 收藏,所以是另一套只有一项的菜单)。

### 7.2 媒体库

| | |
|---|---|
| 区块 | 两级:库列表 → 库内网格(分页 120/页)。库内顶部有排序 + 筛选(类型 / 标签 / 年代 / 评分下限) |
| 加载 | 进库时**并发**拉分面与第一页条目 |
| 失败 | **分面拉不到要在筛选面板里明说**,不能静默变成「此库没有分面」 |
| 空态 | 库内无结果 = 筛选太窄,**保留筛选条**让用户能退回去 |

- **排序一律走服务端。** 本地排只能排到已加载的那一页,翻页后顺序就乱了。
- 排序档位:加入时间 / **更新时间** / 上映日期 / 名称 A→Z、Z→A / 年份 / 评分。
  「更新时间」≠「加入时间」—— 前者是这部剧**最近一集**入库的时间,追更要的是它,两个都得留。
- 评分筛选固定给 **9 / 8 / 7 / 6 四个下限档**(服务端给的分级不是评分,没有分面可列)。
- **这一页必须拿全量(含已屏蔽的库)** —— 它是唯一能把库找回来解除屏蔽的地方。
- **屏蔽是所有人都有的,管理员项才是管理员限定。** 旧版整个右键菜单 admin-only,
  非管理员连菜单都弹不出来。
- 库卡右键与条目卡右键是**两套菜单**(对整个库「标记已看」没意义)。

### 7.3 详情页(剧 / 影 / 季 / 集 四种版式)

| | |
|---|---|
| 区块 | 背景剧照(可调模糊)+ 海报 + 标题 / 年份 / 时长 / 评分 / 标语 + 简介 + 演职员 + **版本选择器** + **线路选择器** + **音轨 / 字幕偏好** + 分集网格(剧)/ 选集栏(集)+ 相似推荐 + 下载入口 |
| 加载 | 详情与媒体信息(版本 / 音轨 / 字幕)**并行**;相似推荐也并发;分集要等详情回来(`series_id` 只有详情才给) |
| 失败 | 媒体信息失败 → 整段不渲染;相似推荐失败 → 静默;分集失败 → 选集栏整条不渲染;**唯独线路清单失败不能静默**(否则线路选择器凭空消失,没人知道为什么) |
| 空态 | 有缓存就**先把缓存画出来,别先清空** —— 无条件清空 = 每次进详情必然闪一下转圈 |

- **版本选择器的「未选」是 `null` 不是 `0`。** 传了 id 核心层就走「手动指定」分支,
  版本筛选正则**整个被跳过**。旧代码用 `0` 初始化,等于每次都替用户选了第一版
  —— 于是版本正则**从上线起一次都没生效过,还一声不吭**。
- **详情页选音轨 / 字幕 = 写偏好,不是当场切轨**(此刻还没起播)。
  写偏好时必须**先取基线再改单项** —— 三项一起覆写会把另两项悄悄清成 null,两头都不报错。
- **进详情页就开始预热「▶ 会播的那个条目」**(头 N MB + 尾 2 MB)。
  换集 / 换版本时要重新预热的是**另一条流**。fire-and-forget,失败全吞。
- **单击进集详情,没有「双击播放」。**【用户定】曾为等双击把单击延后 220 ms,手感发黏。
  播放走缩略图上悬停显现的 ▶。
- 分集卡在「剧集页网格」和「单集页选集栏」**共用同一张**,交互口径必须一样;
  差别只有选集栏多标集号 + 当前集高亮。
- **界面不许撒谎:** 展示的版本必须是**真正会播的那一个**。核心层标 `preferred`,
  UI 用唯一的 `defaultVersion` 算法,**不许自己回落 `versions[0]`**。

### 7.4 搜索(全局 / 库内 / 包括集)

| | |
|---|---|
| 区块 | 输入框 + 两个开关(**包括集** / **聚合跨服**)+ 搜索历史(≤ 8 条)+ 结果(聚合时**按服务器分组**) |
| 加载 | 防抖 250 ms 后打**服务端** search。**不许**"拉全部库 → 全量拉条目 → 本地过滤" |
| 失败 | 半失败(一路 429、一路回空)**不能吞成"没搜到"**,要说清哪台失败了 |
| 空态 | 无 query → 显示历史;有 query 无结果 → 「没搜到」 |

三条开关规则【用户定】:

1. **「包括集」默认关。** 搜「凡人」应该先看到那部剧,不是被 200 集分集淹掉。
2. **「包括集」一拨就重搜;「聚合」一拨不重搜。** 理由不同:聚合一次打 N 台,
   来回拨两下就是 2N 个请求;而「包括集」只多打一次当前服,**不重搜才是坏的**。
3. **库内搜索与聚合互斥。** 有搜索范围时聚合开关**整个不出现**。

- **结果只有一个操作:点 = 进详情,不从这里起播。**
- **跨服结果不给右键菜单** —— 收藏 / 标已看是对当前活跃服务器写的,
  对着别的服的条目按下去会写错地方,而且不报错。
- **类型必须显式传。** 不传时服务端默认包含分集 = 「永远包括集」;
  而且有的服务端带搜索词时会忽略类型参数,所以核心层还要自己再滤一遍。
- 历史只在**用户真的点开了某个结果**时才记(跟着防抖记会把「阿」「阿凡」「阿凡达」全记进去)。

### 7.5 服务器管理 / 线路

| | |
|---|---|
| 区块 | 服务器卡网格:图标 / 名称 / 备注 / 类型徽标 / **连通状态点** / 「当前」角标。搜索过滤 + 拖动排序。右键 → 编辑 / 重新登录 / 服务器线路 / 删除 |
| 加载 | 账号表来自核心层**原序**;连通状态异步探测 |
| 失败 | 删除 / 切换失败在页面内报错,不静默 |
| 空态 | — |

- **备注 / 图标 / 线路 / 排序全部落核心层,不存本地。**
- **状态点 = 连通健康,不是「选中」**(选中看「当前」角标)。
  `down`(探过确实不通)与 `unknown`(还没探过)**同色不同义**,悬停提示必须分开写。
- 编辑弹窗字段顺序【用户定】:服务器名称 / 账号 / 密码 / 备注(+ TLS 开关)。
  **没有地址行** —— 「服务器地址是『服务器线路』里面填写的」。
- **改账号 / 密码必须走重新登录(真登一次换 token)。** 只改字段不重登 = token 还是旧用户的,
  表现为"显示新账号、媒体库还是旧账号的",而且不报错。
- 「服务器线路」是本页最重要的窗:同步 / 添加 / 编辑 / 删除 / 拖动排序,行点击 = 切生效线路。
  **「同步线路」和「测延迟」是两个按钮两回事。**
  线路表为空 = 单线路形态,要补出一行可见主线。**服主没部署同步服务是常态,不能当错误弹。**
- **拖动排序在筛选状态下必须回原表查真实下标**,否则筛选下拖一次就把别的服排乱;
  活跃行要跟着它的 URL 走,只挪数组不挪下标会**静默把用户切到另一条线路上**。
- **任何地方不展示线路地址。**【用户定】只写名称 + 延迟,没起名的回落「线路 N」。

### 7.6 添加服务器 / 首登闸口 / 重新登录

**一份表单定义 + 三种版式。**【核心设计,不许拆】

| 版式 | 形态 |
|---|---|
| 添加页 | 左 nav 选源 + 主从两栏 |
| **首登闸口** | 居中卡片,顶部芯片选源。**它就是添加服务器页的另一种版式,不是另一个页面** |
| 重新登录 | 只有账号密码,**不填地址**【用户定】 |

| | |
|---|---|
| 加载 | 源类型表由核心层给(`source.formSchema`);扫码型源进入即取码,**每 2 s 轮询登录状态**,过期就停,**离页必停** |
| 失败 | 登录失败原样显示后端错误;**改名失败不能把"已经加成功"变成"报错了"** |
| 空态 | — |

- **首登闸口判据要同时看 `emby.currentSession` 和 `source.currentSource`。**
  只判 Emby 会话的话,**纯网盘用户永远进不了门** —— 这是有过的真实故障。
- **二维码是"谁出的图"决定怎么画:** 有的源后端直接返回**渲染好的 PNG**(base64),
  原样贴出即可 —— 把一张二维码图再喂给编码器必然报"数据太大"。
  我们自己的配置搬迁载荷是文本,要自己编码,**纠错级必须和设置页那个出码点一致**。
- **插件贡献的源,登录表单由插件清单声明的字段现渲染。** 不这样的话每接一个插件源
  都要回来改一次宿主,「用户自己做插件自己用」就是空话。插件字段值单独存,别和内置输入框混。
- **本地播放的表单只有一个「选择文件夹」按钮** —— 没有地址框也没有账号密码。
- **局域网三兄弟(SMB / WebDAV / FTP)共用「地址 + 账号密码」,但各给各的占位符**
  —— 在 SMB 的框里摆个 `https://` 只会把人带沟里。账号密码**可留空**(来宾 / 匿名)。
- **重新登录对扫码型源必须给扫码**,不能只给账密框(PC 端曾经是残缺的)。

### 7.7 文件浏览(网盘 / SMB / WebDAV / FTP / 本地)

| | |
|---|---|
| 区块 | 面包屑 + 文件 / 文件夹列表(名称 / 大小 / 修改时间)+ 排序 + 视图切换 |
| 加载 | `source.listDir` 是**流式**的(慢协议要边列边出,见 `SPEC.md` §5.7) |
| 失败 | 凭据失效 → `E_AUTH` → 走重新登录(扫码型给扫码) |
| 空态 | 空目录就说空目录,不要说"加载失败" |

- **进一个源之前先探能力**(`source.capabilities`)。返回"影视目录型" → 走 §7.8 那一页。
- 起播必须走**宿主的起播入口**(要先把独立播放窗拉起来),**本页不许自己起播**。
  > 教训:曾经绕开独立播放窗自己 invoke,结果"有声音、没画面、还关不掉"。

### 7.8 影视目录(VOD 资源站)

> **这一页存在的唯一理由:资源站不是文件树。**
> 上一版把资源站塞进文件浏览页,于是每样东西都得伪装成文件 ——
> 分类伪装成文件夹、翻页伪装成一个叫「下一页」的文件夹、「更新至 17 集」只能拼进文件名。全错。

| | |
|---|---|
| 区块 | 顶部**横条分类**(不是网格里的卡片)+ 海报墙(角标 / 年份 / 评分**各占各的位置**,标题里只有标题)+ 详情**在同一页盖上来** |
| 加载 | 首屏**预抓几页** —— 否则内容铺不满一屏 → 没有滚动 → 无限下拉永远不会被触发。之后滚到底自动续 |
| 失败 | 探能力时抛"不支持" = 这是个文件型源 → **静默换路**退回 §7.7,不当错误弹 |
| 空态 | **有子分类的父级本身多半是空的**,点它要先落到第一个子分类,而不是把用户扔进空页 |

- **单击就打开,不是双击。** 海报墙不是文件管理器。
- **详情盖在同一页上** —— 关掉时网格的滚动位置还在。
- 数据来自影视目录三件套(分类 / 目录 / 详情),**任何实现了它们的源都能用这一页**。

### 7.9 下载

| | |
|---|---|
| 区块 | 任务列表(剧集标题 = SxEy + 集名,电影用整条标题)+ 并发线程数 pill + 每条的删除 ✕ + 「清除已完成」 |
| 加载 | 进页读任务表 + 订阅 `download.progress` 事件 |
| 失败 | 起播已下完的文件失败要如实说 |
| 空态 | — |

- **「清除已完成」只清记录,不删文件**;想删文件的是每条右边那个 ✕。
  两个语义正相反,**别合并成一个命令**。
- **本页不能自己起播**(同 §7.7)。
- 并发数**挂载时把值回灌引擎** —— 否则 pill 显示 3、引擎实际跑 2,双重撒谎。
  > 新架构下这条应当消失:并发数归核心层持久化,UI 只读不灌。**若仍需回灌,说明契约写错了。**
- 已下载条目播放时,**进度要同时回传原服务器和本地记录**(`SPEC.md` §7.6 最后一行)。

### 7.10 收藏

| | |
|---|---|
| 区块 | 海报网格 + 排序 |
| 加载 | 单条命令 |
| 失败 | 整页错误条 |
| 空态 | 「还没有收藏」 |

- **某台 fork 服务器在收藏页忽略 `SortBy`。** 这类补偿一律**下沉核心层**,
  不在 UI 做本地排序 —— 否则三端要各补一次,而漏的那端就是"排序在手机上不生效"。

### 7.11 插件(市场 / 已装 / 源订阅)

- **列不能上背景模糊**(叠内滚会有残影)。

## 8. 播放页与 OSD

> 播放页的行为规格在 `SPEC.md` §7.4(那是三端共同的契约);
> 本节只写 **PC 端的版式与手感**。

### 8.1 版式

播放窗 = 视频层 + OSD 层。**不全屏时常驻标题栏**(§3.4)。

OSD 分区(PC 用鼠标,不必照搬手机的九宫格,但**不许退回"上下两条栏"**):

| 区 | 内容 |
|---|---|
| 顶部 | 返回 / 标题(跑马灯)/ 缓冲速度(出画后)/ 窗口控制 |
| 底部主条 | 进度条(带章节 + 缩略图预览)/ 时间 / 播放控制 / 音量 / 倍速 / 全屏 |
| 底部右侧 | 九个面板入口:版本 · 线路 · 音轨 · 字幕 · 弹幕 · 选集 · 画质 · 更多 · 快捷键 |
| 画面中央 | 未出画时的转圈 + **缓冲速度**;出画后挪到集标题右侧 |

- **面板打开期间上下栏一动不动。**
  > 「点出去闪一下」的根因是**遮罩盖在了 OSD 上面**(层级问题),不是显隐逻辑问题。
- **`Esc` 分级返回**:小浮层 → 面板 → OSD → 才退出播放。

### 8.2 手感

| 项 | 规格 |
|---|---|
| OSD 自动收起 | **5000 ms**。两条例外:**面板开着不收**(用户正在里面挑东西)、**暂停时不收**(暂停就是"我要停下来看看界面") |
| 倍速 | **连续不是档位**:点一下走 0.25,长按每 70 ms 走 0.05(≈0.7×/秒,从 1 拉到 3 要 3 秒)。「既不会手一抖就飞过去,也不会按到手酸」 |
| 标题跑马灯 | ① 放得下就不滚 ② 速度 **30 px/s**,**不能写死总时长**(写死 = 标题越长划得越快,长剧名根本来不及看清)③ 完整滚一圈**不来回弹**(上一版"滚到末尾再倒回来",用户原话:「很丑」)④ 两头各留 18% 停顿,下限 12 s |
| 选集列表 | **带封面的行**:封面 \| 第一行 = 季集(+ 集名)\| 第二行 = 时长 · 分辨率 · 码率。播放中只拉一屏 40 条 |
| 缓冲速度 | 0 或负数 → **什么都不画** |
| 线路面板 | **先出表(零等待、立刻可点),再逐条探**。状态是**三态**:未探(转圈)/ 探过但不通(显示「—」,**不装成 0 ms**)/ 毫秒数。按延迟分三档、组内升序,**挂掉的单独归最后**(慢和不通是两件事);打开面板要**滚动到当前线路** |
| seek 卡死提示 | 有的服务器宣称支持 Range 却回整个文件,跳 9 分钟就是几百 MB。**播放器修不了,但必须提示「正在跳转…」**,一次 seek 只说一次,跳完复位 |

> 选集列表用封面行的理由:播放中换集,用户是**靠画面认集**的 ——
> 「第 7 集」这三个字唤不起记忆,一张剧照可以。

### 8.3 弹幕层

- 渲染走核心层的 `osd-overlay`(`SPEC.md` §7.5),**不占字幕轨**。
- **PC 端 UI 不画弹幕**,只发开关与样式设置。
- 时钟快照结构固定 `{base, stamp, paused, speed}`,插值 `t = base + (now-stamp) * speed`。
  **必须乘倍速** —— 这是"倍速下弹幕一顿一顿"的真根因,**和绘制开销毫无关系**
  (当年为此换过整个渲染引擎,白换)。

### 8.4 起播与收尾(PC 特有的部分)

- **外部播放器必须在调 `player.play` 之前判。** 之后再拉外部播放器 =
  两个播放器同时出声(本项目栽过)。
- **换片时先立"未就绪"再发命令**,不能排在两个 await 之后。
- **撤黑幕的判据是"时间真的往前走了"**,不是 `time > 0`。另需 4 s 兜底,
  但兜底放行前**必须先确认不在等缓冲**。
- **`duration == 0` 时进度条禁用**,并且不许用 0 盖掉已知时长。
- **播完收尾传总时长,不是当前时间**(差最后零点几秒 = 服务端不算看完,Trakt / Bangumi 一次都不触发)。

## 9. 无障碍

**不做完整的读屏适配,但这四条是底线**(它们同时也让普通用户受益):

| 项 | 要求 |
|---|---|
| 键盘可达 | 每个可点元素都能 `Tab` 到并用 `回车` / `空格` 触发(§5.5) |
| 焦点可见 | 键盘导航时焦点环必须**清晰且不被裁**(§5.5 最后一条) |
| 对比度 | 正文墨色对底色 ≥ **4.5:1**,次要文字 ≥ **3:1**。**两套主题都要量**,不是只量深色 |
| 系统缩放 | 支持 Windows 125% / 150% / 175%。**布局不许在 175% 下溢出或截断** |

- 深浅两套主题的对比度**必须有一条自动检查**(遍历 token 组合算对比度),
  否则改一次配色就可能悄悄破一条。
- **不用颜色作为唯一信息载体。** 服务器状态点已经踩过边:`down` 与 `unknown` 同色不同义,
  必须靠悬停文字区分。

## 10. 性能预算与落法

### 10.1 预算(越线即红)

| 指标 | 预算 |
|---|---|
| 冷启动到首屏骨架 | ≤ **400 ms** |
| 冷启动到首页有内容 | ≤ **1.5 s**(局域网服务器) |
| 页面切换到骨架 | ≤ **100 ms** |
| 滚动帧率 | **60 fps**,掉帧率 < 1% |
| 进度条拖动延迟 | ≤ **1 帧** |
| 空闲内存(UI 进程) | ≤ **250 MB** |

核心层侧的预算见 `SPEC.md` §14.7。

### 10.2 落法

| 手段 | 说明 |
|---|---|
| **虚拟化列表** | 所有网格与长列表走 Avalonia 的虚拟化面板。媒体库 5000 条必须能滚 |
| **图片按需解码** | 屏外不解码不排版。图片走数据通道 `/img?src=&w=`,**由 UI 传期望宽度**,核心层决定实际取多大 |
| **各块独立加载态** | 页面**不持有一个全局 loading**(§6.4) |
| **同面板内请求并发** | 串行 await 会把后端本身的卡**放大 N 倍**(设置页的字幕翻译面板曾放大四倍) |
| **分页拉分集** | 【实测】最长那部剧 2648 集:全量 1813.9 KB / 1841 ms,分页 30 条 **20.0 KB / 435 ms** |
| **跟手绕过绑定** | §2.3 第 3 条 |
| **悬停触发的请求要缓存** | 且"查过 = 没有"必须能表示(§7.12 空态那条) |

### 10.3 缓存口径

| 缓存 | 口径 |
|---|---|
| 详情 | **内存 TTL 5 分钟,不落盘。** 里面带续播进度 / 收藏 / 已看,随时会变还会被别的设备改。落盘跨重启复用 = **给自己造一个"进度莫名回退"的 bug** |
| 列表 | 缓存,**尤其为了返回键**(返回时不许重新拉,§5.4) |
| 随机推荐 | **也要缓存**。它每次返回不同条目,不缓存 = 每次退回首页都要重新下 5 张大图。5 分钟内保持同一批,过期自然换新,随机性没丢 |
| 图片 | 按 tag 基本不可变,**该落盘**。上限见 `SPEC.md` §14.2 |
| 失效 | 整体清,不定点清。**切服务器 / 切线路 / 重登必须清详情缓存** |
| 缓存键 | **必须编进全部入参**,而且"形状不同的同名数据"要分池 |

### 11.5 自检手段

代码编译绿 + 单测绿**照不到**布局、可见性、时序这一类 bug。PC 端的手段:

| 要验什么 | 手段 |
|---|---|
| 真实布局与遮挡 | **Avalonia.Headless 渲染 + 截图对账**;需要"谁盖住了谁"时做命中测试 |
| 视频层确实在画 | **不能只看命令返回值。** 要有一个"这一帧真的有画面"的探针 |
| 窗口几何(最大化溢出、DPI) | 真窗口 + 平台 API 量位置,headless 量不到 |
| 纯逻辑(算法、格式化) | 单测直跑**本尊模块**,**不许抄副本** —— 抄副本测的是副本,永远绿。本仓栽过两次 |

> **新测试必须先红。** 反向注入一个真 bug 确认它变红,再修好。
> 假绿的五种形态:注入不忠实 / 环境不同 / 夹具不真实 / 语料选错 /
> **断言的时序让 bug 没机会发生**(清理类断言最易测成空集)。
