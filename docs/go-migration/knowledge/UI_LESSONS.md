# 前端经验甄别

> 面向 Go 核心 + 原生 UI(Compose / Avalonia / SwiftUI)重写。
> 本文只做一件事:把 `ui/desktop` `ui/mobile` `ui/tv` `ui/shared` 里沉下来的经验分成三类,
> 说清哪些**必须带走**、哪些**不用管**、哪些**会自己消失**。
> 所有结论带 `文件:行号` 出处;读不出来的写「未确认」并说明查过哪里。

## 0. 一句话 + 三分类的判定方法

**一句话**:这套 React 前端里真正值钱的不是组件,是**「界面在什么时候说了谎」的账本** ——
近三年的用户报障里,压倒性多数根因是「后端做对了、界面显示的是另一回事,且两边都不报错」。
换 UI 框架带不走组件,但必须带走这本账。

### 判定方法(逐条问三个问题,按序短路)

| 序 | 问题 | 是 → 归类 |
|---|---|---|
| 1 | 这条经验里出现的名词,有没有一个只存在于浏览器?(DOM / CSS / 事件冒泡 / 合成器 / localStorage / `<input>` / 层叠上下文) | **B 类**——原生 UI 下这些名词不存在 |
| 2 | 去掉「React / Tauri invoke / 三套独立前端」这三个前提后,这条经验还剩下什么? 什么都不剩 | **C 类**——架构产物 |
| 3 | 剩下的是**用户能感知的行为约定**(显示什么/什么时候显示/不显示什么/失败时说什么) | **A 类**——必须继承 |

判不清的一律进第 7 节「存疑」,不硬塞。

### 一个容易分错的例子(说明为什么要按序问)

`ui/shared/Danmaku.tsx` 的弹幕轨道分配与倍速插值,**看起来**是「Canvas 绘制代码」(像 B 类),
实际上它是本项目**唯一**的弹幕渲染实现:mpv/ASS 那条路已于 2026-07-27 `108965f6` 整条删除,
理由写在 `ui/desktop/App.tsx:141` —— mpv 的次字幕位只有一个,弹幕占了就开不了双语字幕,
「一个设置项换来两个功能互斥,不如把它去掉」。
所以它过不了第 1 问(轨道分配、碰撞避让、倍速插值都不依赖浏览器),是 **A 类**,必须整体搬进新核心层。

## 1. A 类:产品与交互知识(必须继承)

> 排序按「丢了最疼」。每条给出处;`ui/…` 路径相对仓库根。

### 1.1 界面不许撒谎 —— 显示的必须是真实生效的那一个

这一组是本项目最贵的一类 bug:**后端做对了,界面显示另一回事,而且两边都不报错**。
用户看到的是「功能没生效」,于是去改设置、去重装,永远查不到真因。

#### A-1 版本选择器高亮的必须是「核层实际挑中的那条」,不是列表第一条
- **知识**:详情页/播放器的「版本」列表,选中态来自核层标记的 `preferred`(正则命中 ＞ 第一条),不能用下标 `0`,更不能用 `i===0`。
- **为什么**:版本筛选正则明明生效、放的是第二条,面板却一直高亮第一条,连「播放信息」的规格也是第一条的 —— 用户照着界面看,只能得出「正则根本没生效」(2026-07-30 挂真机复现)。
- **Compose**:`MediaVersion` 数据类带 `preferred: Boolean`,UI 只做 `versions.firstOrNull { it.preferred } ?: versions.first()`;禁止在 UI 层重算挑选规则。
- **Avalonia**:同上,`SelectedItem` 绑到 VM 里由核心层算好的 `DefaultVersion`,不要绑 `Items[0]`。
- **出处**:`ui/desktop/App.tsx:1133`、`ui/desktop/App.tsx:1553`、`ui/shared/api.ts:142`

#### A-2 「已生效」这三个字必须有真凭据 —— 超分看 `will_run`,不看 `count`
- **知识**:挂载滤镜后 `count>0` 只说明播放器收下了路径,不代表 shader 会跑;Anime4K 每个 pass 都带「输出 > 源 ×1.2」门槛,窗口没比源大时整条链一帧都不跑。必须回读 `will_run` 并把核层给的 note(带真实数字)原话转给用户。
- **为什么**:这是本项目自己撒过的谎 —— 旧文案在整条链空转时还在说「已生效 · 挂载 6 个」。
- **Compose / Avalonia**:凡是「已开启/已生效」型反馈,核心层必须回一个可验证的布尔 + 一句人话说明,UI 只负责转述,不自己下结论。
- **出处**:`ui/desktop/App.tsx:1341`、`ui/shared/api.ts:890`、`ui/mobile/pages/PlayerPage.tsx:1121`

#### A-3 面板初值一律回读播放器真值,不许用前端猜的默认
- **知识**:字幕位置/缩放/字体、硬解档位、杜比软解开关,起播后都要从播放器回读一次再渲染。
- **为什么**:曾把次字幕位置写死 100(mpv 真默认是 0=顶部),面板一打开就显示「位置 100」而画面上顶着;杜比软解那行恒初始化 false,于是「已经在软解、开关却显示关」。**初值和真实值对不上 = 用户还没动就已经在被骗**。
- **Compose / Avalonia**:播放器状态一律单向 `播放器 → VM → UI`,UI 不持有「我以为是多少」的影子副本。
- **出处**:`ui/desktop/App.tsx:334`、`ui/desktop/App.tsx:346`、`ui/desktop/App.tsx:672`

#### A-4 「搜不到」和「搜不了」是两件事
- **知识**:上游返回的 errorCode 要原样抛到界面(最常见是 429 配额上限),不能把接口故障吞成空表。
- **为什么**:以前这类失败统一显示「未找到匹配的弹幕」,把「官方源整天在回 429」说成了「这片没有弹幕」。
- **Compose / Avalonia**:列表空态至少分三种:`空(确实没有)` / `失败(带原因)` / `未搜索`。别用一个 `emptyList()` 兼职三种语义。
- **出处**:`ui/desktop/App.tsx:542`

#### A-5 「查不动」≠「已是最新」
- **知识**:检查更新失败必须报错,不能显示「已是最新版本」。
- **出处**:`ui/desktop/pages/SettingsPage.tsx:2709`

#### A-6 一个端点 404 不等于「用户库是空的」
- **知识**:`/Items/Counts` 在某些 Emby fork 上是 404,那台就是一排 0。判「库是不是空的」要看 resume 和 views,不能看 counts。
- **出处**:`ui/shared/api.ts:973`

### 1.2 失败、空态与「拒绝 vs 夹紧」的口径

#### A-7 用户点取消不是失败
- **知识**:系统文件/文件夹选择器返回 null = 用户按了取消,**什么都别做**。弹一句「添加失败」是在骂用户按了取消。
- **出处**:`ui/shared/api.ts:1332`、`ui/desktop/pages/SettingsPage.tsx:437`

#### A-8 空数组是合法值,不是错误 —— 而且各有各的空态版式
- **知识**:以下全都「空是常态」,UI 必须为空排一版,而不是留一块空白或报错:
  - 相似推荐空 → 整段不渲染(`ui/shared/api.ts:756`)
  - 演职员 `overview` 空是常态(只有刮到 TMDB 人物页才有生平)→ 要为「没有生平」排一版(`ui/shared/api.ts:760`)
  - 标语实测只有 34% 的条目有 → 没值**整行不画**,不留空位(`ui/shared/api.ts:189`)
  - 季列表空是合法的(有些剧集直接挂剧下)→ 回落成拿 seriesId 当 parent 拉分集;不回落的表现是「点进去一集都没有」且不报错(`ui/shared/api.ts:782`)
  - 章节空 = 没刮削 → 跳片头片尾与进度条缩略图**自动静默不工作**,这是正常情况(`ui/shared/api.ts:1439`)
  - 条目分类空数组 = 元数据没刮到 = 不知道,按「允许」处理,别自作主张填假值(`ui/shared/api.ts:550`)

#### A-9 越界值让核心层拒绝并说话,UI 不许先 clamp
- **知识**:预取线程数(2~4)、缓存大小(≥16MB)、预加载头部量(≤512MB)这类,核心层是**拒绝**不是夹紧;所以 UI 的 Stepper min/max 只做常规引导,**绝不能先把值夹好再提交**。
- **为什么**:先夹的话,用户点到上限会毫无反应,而错误信息(「预取线程数只支持 2~4」)正是唯一的反馈来源。同理跨服回传 range 对未知值是拒绝而非回落 "all" —— 静默回落会让选了「仅初次」的用户在写所有服务器。
- **Compose / Avalonia**:数值输入不做客户端夹紧,提交失败原样显示核心层的错误文案。
- **出处**:`ui/desktop/pages/SettingsPage.tsx:1738`、`ui/desktop/pages/SettingsPage.tsx:1854`、`ui/desktop/pages/SettingsPage.tsx:2067`、`ui/shared/api.ts:1393`、`ui/shared/api.ts:1407`

#### A-10 开关落盘失败必须回滚 UI
- **知识**:点开关 → 调命令 → 失败 → **把开关拨回去**。
- **为什么**:否则开关停在「开」而磁盘是「关」,用户下次起播发现没生效,回来一看开关明明开着。
- **出处**:`ui/desktop/pages/SettingsPage.tsx:458`、`ui/desktop/pages/SettingsPage.tsx:471`、`ui/desktop/pages/SettingsPage.tsx:287`

#### A-11 「起播头几拍失败」可以静默,「一直失败」不行
- **知识**:状态轮询前 8 拍(2s)失败照旧静默,之后说一次,只说一次不刷屏。
- **为什么**:老代码是空 catch,把持续失败一并咽了 —— 表现为「进度条停在上次看到的地方一动不动」而画面在正常播。**这类故障只能靠猜,就是因为它一声不吭**。
- **出处**:`ui/desktop/App.tsx:1065`

#### A-12 收尾链路上「失败也要往下走」
- **知识**:退出播放的顺序是 `落库进度 → 关窗`;落库失败**不能**中断关窗。
- **为什么**:「没在播」时 stop 会报错(关一个空播放窗正是这种情况),让它抛出去的话窗口就**关不掉**了。**进度落库失败是遗憾,窗口关不掉是故障**。
- **出处**:`ui/desktop/App.tsx:888`、`ui/desktop/App.tsx:899`

#### A-13 物理上限要如实说明并留兜底
- **知识**:配置二维码载荷是加密+压缩后的服务器配置,账号一多就超出二维码容量(纠错级 L ~2.9KB),此时如实说明并留**文本载荷**兜底,别静默不出图。
- **出处**:`ui/desktop/pages/SettingsPage.tsx:2824`

### 1.3 播放页:起播、进度、收尾

#### A-14 起播的第一件事是把黑幕放回来,**必须在任何 await 之前**
- **知识**:换片时立刻置「未就绪」并盖黑幕,不能排在 `getPlaybackPrefs()` / `play()` 之后。
- **为什么**:用户 2026-08-02:「播放第二个视频,缓冲出来之前的背景是之前视频的画面」。根因不是没人复位,是**复位排在两个 await 后面**,而 play() 要走 PlaybackInfo → 取流 → 起代理,慢服上是好几秒;那几秒里播放器 `keep-open=yes` 让上一集停在最后一帧没卸载。
- **Compose / Avalonia**:换片是一个同步的状态跃迁(`Loading` 态先立),异步取流在后。别把遮罩的生死挂在异步结果上。
- **出处**:`ui/desktop/App.tsx:685`

#### A-15 撤黑幕的判据是「时间真的往前走了」,不是 `time > 0`
- **知识**:续播时核心层一 loadfile 就把位置记账成续播点,第一拍读到的就已经 >0。用 `>0` 判 = 起播即放行,缓冲还没出画就把上一片残帧亮出来。另需 4s 兜底(暂停起播/静止首帧时间不走),但兜底放行前**必须先确认不在等缓冲**。
- **出处**:`ui/desktop/App.tsx:1030`、`ui/desktop/App.tsx:1014`、`ui/mobile/pages/PlayerPage.tsx:124`、`ui/mobile/pages/PlayerPage.tsx:292`

#### A-16 `duration = 0` 绝不能盖掉已知时长 —— 塌掉的量程比没有量程更危险
- **知识**:起播时用媒体元数据的 runtime 先播下时长;播放器每次 loadfile 把 duration 记账清回 0,要到 FILE_LOADED 才报得出来。这中间几拍照单全收的话,进度条量程塌成 `max(1, 0)` = **1 秒**。
- **为什么**:用户点在条中间,算出来的目标是 0.5 秒而不是片长的一半 → 「点了跳转,画面没动」。同源问题:双击快进的上界必须写 `duration || Infinity`,**不能** `|| 0`(否则加载期双击快进会跳回片头);时长未知时干脆不接受拖动。
- **出处**:`ui/desktop/App.tsx:1021`、`ui/mobile/pages/PlayerPage.tsx:630`、`ui/mobile/pages/PlayerPage.tsx:392`、`ui/mobile/pages/PlayerPage.tsx:840`

#### A-17 seek 是排队命令:松手后先等核心层收下,再放开「拖动中」
- **知识**:提交 seek → 等它返回 → 才把 UI 的拖动值交还给轮询值;失败也要放开。拖动期间**只改本地显示,不每帧发命令**。
- **为什么**:同步放开的话,`当前时间 = 拖动值 ?? 轮询值`,中间那段轮询会读到拖动前的旧位置 —— 进度条先弹回原处再跳到新位置(「拖一下条自己乱跳」)。每帧发 seek 会把播放器命令队列灌满(「拖着拖着卡住」)。失败不放开会把进度条永久钉死。
- **Compose / Avalonia**:滑块用「拖动中的本地值」覆盖「上游值」,`onValueChangeFinished` 才发命令,并保持覆盖到命令返回。
- **出处**:`ui/desktop/App.tsx:860`、`ui/desktop/App.tsx:867`、`ui/mobile/pages/PlayerPage.tsx:468`、`ui/mobile/pages/PlayerPage.tsx:1387`

#### A-18 自动跳过片头/片尾的两条闸
- **知识**:① **每片各跳一次** —— 不设这个闸,用户手动倒回去看片头会被立刻再踹走,等于「退不回去」;② **片尾只在后面还有东西(下集预告)时才跳** —— 片尾是最后一章时 seek 过去等于强行结束这一集,用户要的是跳过片尾不是提前结束。
- **配套**:在播放页翻这两个开关后,**必须重拉一次章节**(intro/outro 是核心层按开关算好的,开关变了那两个值就过期了);不重拉 = 用户在片头前打开开关,这一集照样不跳,而开关明明是开的。
- **出处**:`ui/desktop/App.tsx:549`、`ui/desktop/App.tsx:591`、`ui/shared/api.ts:1446`

#### A-19 播完收尾必须传总时长,不是当前时间
- **知识**:正常播到结尾时,落库位置传 `duration`。
- **为什么**:播放器停在最后一帧时 time 通常差最后零点几秒,传 time 算出来 99%,服务端不算「看完」,Trakt/Bangumi 一次都不触发。另:`keep-open` 下播放器**永远不发 END_FILE**,判播完只能读 `eof` 属性,而且要上锁(eof 会一直为 true,回调每 500ms 跑一次)。
- **出处**:`ui/desktop/App.tsx:884`、`ui/desktop/App.tsx:1054`、`ui/mobile/pages/PlayerPage.tsx:305`、`ui/shared/api.ts:222`

#### A-20 修不了的事也要说出来 —— seek 卡死
- **知识**:某些服务器宣称支持 Range 却对 Range 请求回 200 + 整个文件,ffmpeg 只能顺读丢弃到目标字节,跳 9 分钟就是几百 MB。播放器修不了,但必须提示「正在跳转…」类信息;**一次 seek 只说一次**,跳完复位。
- **为什么**:否则用户对着一个不动的进度条干等,以为是软件坏了。
- **出处**:`ui/desktop/App.tsx:1037`、`ui/mobile/pages/PlayerPage.tsx:295`、`ui/shared/api.ts:226`

#### A-21 音轨/字幕表要轮询到位,而且别在「第一次非空」就停
- **知识**:网络流 demux 慢,内封轨起播后几秒才出现,外挂字幕更晚(要等 FILE_LOADED)。做法:起播后每 700ms 探一次,~11s(16 次)兜底;换集/换版本自动重来。
- **为什么**:只在起播后拉一枪,表现为「字幕只有关闭/外挂、音轨整条不显示」(2026-07-16 报的);只在第一次非空就停,则音轨先出来、字幕永远进不了面板(TV 端原先就是这个残缺版)。
- **配套**:详情页起播前挑好的音轨/字幕,要在**第一次拿到非空轨表时落实一次**,之后用户在 OSD 里手动切的优先级更高,不能被反复顶掉;落实后立即清空(它描述「这一次起播」,不是持久偏好)。
- **出处**:`ui/desktop/App.tsx:1115`、`ui/desktop/App.tsx:1121`、`ui/mobile/pages/PlayerPage.tsx:330`

### 1.4 播放页:OSD 版式与手感(用户逐条定的规格)

#### A-22 OSD 用满整个屏幕,不要只堆上下两条栏
- **知识**:手机端 OSD 是用户 2026-07-28 亲自定的九宫格:左上 返回+标题 / 右上 版本·线路·超分·更多 / 左中 截图·锁屏 / 右中 倍速条 / 左下 上一集·下一集 / 中下 快退·播放暂停·快进 / 右下 音频·弹幕·选集。
- **为什么**:上一版把东西全堆进上下两条栏,**屏幕两侧和中间全空着**,遮挡 83.6%。
- **Compose**:这是布局规格,按九宫格 `Box` + 九个 `Modifier.align` 落,别退回 TopBar/BottomBar 两条。
- **出处**:`ui/mobile/pages/PlayerPage.tsx:52`

#### A-23 OSD 的自动收起有两条例外
- **知识**:超时 5000ms(= Media3 `PlayerControlView.DEFAULT_SHOW_TIMEOUT_MS`,安卓上别的播放器都是这个数,不要自己发明);但**面板开着不收**(用户正在里面挑东西),**暂停时也不收**(暂停就是「我要停下来看看界面」)。
- **出处**:`ui/mobile/pages/PlayerPage.tsx:87`、`ui/mobile/pages/PlayerPage.tsx:369`

#### A-24 倍速是连续的,不是档位
- **知识**:点一下走 0.25(一档),长按每 70ms 走 0.05(≈0.7×/秒:从 1 拉到 3 要 3 秒)。「既不会手一抖就飞过去,也不会按到手酸」。
- **出处**:`ui/mobile/pages/PlayerPage.tsx:77`

#### A-25 标题只在放不下时跑马灯,而且是无缝循环、速度按溢出量算
- **知识**:① 放得下就不滚(短标题白晃眼);② 速度 30px/s 是舒适阅读速度,**不能写死总时长** —— 写死时长 = 标题越长划得越快,长剧名根本来不及看清(用户 2026-07-30);③ 完整滚一圈不来回弹(上一版「滚到末尾再倒回来」,用户原话:「很丑」);④ 关键帧两头各留 18% 停顿,下限 12s。
- **出处**:`ui/desktop/App.tsx:1221`、`ui/mobile/pages/PlayerPage.tsx:516`

#### A-26 播放中的选集列表用**带封面的行**
- **知识**:封面 | 第一行 = 季集(+集名) / 第二行 = 时长 · 分辨率 · 码率。播放中只拉一屏 40 条(播放中换集是「翻翻附近几集」,通读全季该回详情页)。
- **为什么**:播放中换集,用户是**靠画面认集**的 —— 「第 7 集」这三个字唤不起记忆,一张剧照可以。
- **出处**:`ui/mobile/pages/PlayerPage.tsx:1217`、`ui/mobile/pages/PlayerPage.tsx:244`

#### A-27 按**真实解码尺寸**自动横竖屏,不按元数据
- **知识**:判据用播放器报上来的实际画面宽高,不是条目元数据(元数据经常错:转码版本、竖屏短剧被标成 16:9)。只在拿到尺寸之后才下达(起播前就锁横屏,竖屏短片会先被硬掰过去再掰回来);**离开播放页必须交回系统**(不交的话列表页也被钉死在横屏,用户不知道去哪解开);纯音频不动方向。
- **出处**:`ui/mobile/pages/PlayerPage.tsx:173`

#### A-28 线路面板:先出表,再逐条探;三态不能压成两态
- **知识**:线路表直接从本地账号配置渲染(零等待、立刻可点),再对每条线各发一个探测各回各的。状态是**三态**:`未探(转圈)` / `探过但不通(显示「—」,不装成 0ms)` / `毫秒数`。几十条线路要**按延迟分三档**、组内升序,挂掉的单独归最后(**慢和不通是两件事**);打开面板要**滚动到当前线路**。
- **为什么**:用户 2026-07-16 原话「不然一条线路探了好久,一直卡在那怎么办?」——旧写法整表一次性返回,一条死线(最坏 6s 超时)就扣住整个面板,而用户打开这个面板十有八九正是因为当前线路不通。
- **出处**:`ui/desktop/App.tsx:301`、`ui/desktop/App.tsx:1143`、`ui/mobile/pages/PlayerPage.tsx:1038`、`ui/mobile/pages/PlayerPage.tsx:656`

#### A-29 任何地方都不展示线路地址
- **知识**:线路条目只写**名称 + 延迟**。没起名字的线路回落成「线路 N」,**不是**回落成 URL。
- **为什么**:用户 2026-08-02 明确要求「在任何地方都不要展示具体的线路地址」。
- **出处**:`ui/mobile/pages/PlayerPage.tsx:1070`


> **2026-09-06 用户改口:线路页要显示具体地址。**
> 理由是「只写线路一/线路二 + 生效中,根本认不出哪条是哪条」——
> 两条同名线路在界面上就是同一行。改动**只限线路页那一处**:
> 首页/聚合页的服务器名旁边仍然不写地址(那里地址只是内部键)。

#### A-30 切线路后必须把会话一起刷
- **知识**:切完线路要重拉会话 —— 封面/剧照/缩略图/人物图的 URL 全是拿会话里的服务器地址现拼的。
- **为什么**:不刷的话,用户正因为旧线不通才切线路,切完图片继续打那条死线,看起来「切了跟没切一样」。
- **出处**:`ui/desktop/App.tsx:1193`

#### A-31 缓冲速度为 0 时什么都不画
- **知识**:`0 / 负数 → 空串`。本地文件、缓存喂饱时缓冲速度本来就是 0,画一个「0 KB/s」会让人以为卡住了。显示位置:没出画之前在**画面正中**,出画之后挪到**集标题右侧**(用户 2026-08-02 口径)。
- **出处**:`ui/shared/api.ts:934`、`ui/mobile/pages/PlayerPage.tsx:124`

#### A-32 截图落盘位置要说实话
- **知识**:安卓上截图落在**应用外部专属目录**,不是系统相册(往相册写要过 MediaStore,那是宿主的活)。文案必须跟实话说。
- **出处**:`ui/mobile/pages/PlayerPage.tsx:795`

#### A-33 外部播放器必须在起播**之前**判
- **知识**:配置了外部播放器就整条交出去,不进内置播放页 —— 判断必须在调 `play()` 之前。起不来时如实报错并回落内置播放器(外部程序可能被杀毒删了/被挪走了)。
- **为什么**:之后再拉外部播放器 = 两个播放器同时出声(本项目栽过)。
- **出处**:`ui/desktop/App.tsx:698`

#### A-34 播放器的窗口态要**回读**,不能自己记账
- **知识**:全屏/最大化的图标状态每次都从窗口回读。用户从系统侧(双击标题栏、Win+↑、热键)改窗口态时,只在点击时翻标志位的写法迟早和真实状态对不上。另:播放中不渲染常规标题栏时,必须自绘一组窗口控制(最小化/窗口化/全屏各有各的按钮)—— 用户 2026-07-16 报「点了全屏就一直全屏,根本没有其他操作」,根因不是退不出去,是**界面上看不出来还能退**。
- **出处**:`ui/desktop/App.tsx:966`

### 1.5 弹幕:整体搬进新核心层

> 背景:mpv/ASS 那条渲染路已于 2026-07-27 `108965f6` 整条删除,理由见 `ui/desktop/App.tsx:141` ——
> mpv 的次字幕位只有一个,弹幕占了就开不了双语字幕,「一个设置项换来两个功能互斥,不如把它去掉」。
> 所以下面这些**是当前唯一的弹幕实现**,不是「网页 fallback」。

#### A-35 播放时钟快照必须带倍速因子
- **知识**:弹幕跑 60fps,而播放状态是 250ms~1s 一拍轮询,两拍之间靠墙钟外推。外推时**必须乘倍速**。
- **为什么**:这是「倍速下弹幕一顿一顿」的真根因 —— 2x 播放时弹幕按 1x 爬,每拍被真值硬拽回去一次。**和绘制开销毫无关系**,当年为此换过整个渲染引擎(白换)。
- **Compose / Avalonia**:时钟快照结构固定为 `{base, stamp, paused, speed}`,插值 `t = base + (now-stamp)*speed`。
- **出处**:`ui/shared/Danmaku.tsx:8`、`ui/shared/Danmaku.tsx:94`、`ui/mobile/pages/PlayerPage.tsx:146`

#### A-36 轨道分配:每条轨记「空出时刻」,不要每帧扫在屏弹幕
- **知识**:维护 `laneFree[lane] = 该轨腾空的时间点`。新弹幕优先选已空出的轨,否则选最快空出的那条。滚动弹幕速度 `= (画布宽 + 文本宽) / duration`,占用到 `t + (文本宽 + 字号) / 速度`。顶/底弹幕(mode 4/5)按已占用 lane 集合避让。
- **为什么**:旧写法对**全量在屏弹幕**做 filter+slice,外面还套轨道数循环 = 每生成一条弹幕 O(轨道数 × 在屏条数)。**弹幕一密就是这里在掉帧**。
- **出处**:`ui/shared/Danmaku.tsx:122`(算法实体在 `ui/shared/Danmaku.tsx:109-135`)

#### A-37 seek 检测与暂停跳帧
- **知识**:`t < 上帧 - 0.5` 或 `t > 上帧 + 3` 判为大跳 → 清屏 + 二分/线性重定位游标。暂停时时间不动 = 画面不会变 → **整帧完全跳过**(连清屏都省)。`-1` 表示「必须重画」(尺寸变了/换片/刚恢复播放)。
- **出处**:`ui/shared/Danmaku.tsx:67`、`ui/shared/Danmaku.tsx:100`

#### A-38 弹幕的「显示速度 / 字体大小」是**渲染参数**,归 UI 侧;但必须持久化
- **知识**:核心层的 danmaku 模块只管源 CRUD + 搜索/匹配/过滤,没有任何显示配置。速度/字号/不透明度/显示区域/开关这五项归渲染侧。**但必须落盘** —— 用户 2026-07-16:「在某一集调整了,后续就不用再重新调整」;换片会重建整个播放器状态,不落盘就每集都要重调。
- **★ 读回存档必须逐项夹紧**:档位表增删过之后旧下标可能越界 → 取到 undefined → 解构直接崩在渲染里。
- **出处**:`ui/desktop/App.tsx:128`、`ui/desktop/App.tsx:151`、`ui/desktop/App.tsx:166`、`ui/shared/Danmaku.tsx:18`

#### A-39 弹幕开关是用户的持久化偏好,自动匹配不许擅自翻它
- **知识**:默认**开**;自动匹配成功后**不要**把开关顶开(顶开 = 用户关不掉);换片**不要**把开关拍回关(拍回 = 上一集调好的下一集全废)。没匹配到时评论为空,开着也只是一层空画布。
- **出处**:`ui/desktop/App.tsx:160`、`ui/desktop/App.tsx:630`

#### A-40 弹幕匹配喂的是**真实发布文件名**,不是条目名
- **知识**:`/match` 是按文件名做跨语种解析的那条路。喂「第 35 集」等于整条路白跑(实测返回的第一名是完全无关的片)。取值:Emby 的 `MediaSource.Name` 就是不含扩展名的真文件名;网盘/下载有 path 直接取 basename。另需给出**平行语料**(条目名、原名、别名)—— 库里是中文名而弹幕源收的是日文名时,单靠 title 一路恒 0 分。
- **出处**:`ui/desktop/App.tsx:508`、`ui/mobile/pages/PlayerPage.tsx:257`、`ui/shared/api.ts:536`

#### A-41 别在自动匹配之后又手动匹配一轮
- **知识**:核心层的自动加载内部已跑过全网匹配并按分数门槛筛过;之后再用**同样的入参、同样的判据**发一轮,结果恒为「可信度不足」,却实打实又发了一整轮请求 —— **每一次没匹配上的起播 = 双倍配额,零收益**。
- **出处**:`ui/desktop/App.tsx:534`

> ⚠️ 弹幕还有一条**当前就是坏的**:屏蔽词/过滤器核心层有、前端零接线,而界面已经在承诺它。
> 见本文 §1-补 的 **A-61**(它排在 §2 之后,别漏)。

### 1.6 设置、表单与账号

#### A-42 设置页「改完即生效」,全页没有保存按钮、没有二次确认
- **知识**:输入框 blur 落盘、开关/分段点按即调命令,绿字或 toast 反馈。整个设置页(12 面板 / ~90 项)**一个「保存」按钮都没有,一个确认框都没有**。
- **为什么**:这是刻意的产品决定,不是漏做。反例就在同一份代码里:「播放流也走代理」曾经只改本地态不落盘 —— 拨一下走开就没了,还什么都不报。
- **但**:**不可逆的破坏性操作仍然要确认** —— 删服务器有独立确认弹窗,且「删除」用危险色、和「取消」不等权重(原生 confirm 的两个按钮长得一模一样,那不行)。
- **Compose / Avalonia**:设置项 = 立即提交 + 失败回滚(见 A-10);确认框只留给不可逆动作。
- **出处**:`ui/desktop/pages/SettingsPage.tsx:114`、`ui/desktop/pages/SettingsPage.tsx:1969`、`ui/desktop/app/Sidebar.tsx:143`

#### A-43 新增一个设置项 = 落配置 + **加消费点**,少一半就是假开关
- **知识**:「加字段 → 在起播时应用 → 才算做完」。只加字段不加消费点,就是又造一个「存得下、没人读」的假开关。
- **为什么**:2026-07-19 之前播放器那 6 项只存在浏览器本地,Prefs 里根本没有字段;页面上还挂着一段「核心尚无落点」的说明 —— **说明是诚实的,但功能是死的**。
- **出处**:`ui/desktop/pages/SettingsPage.tsx:333`、`ui/shared/api.ts:1412`

#### A-44 正则校验必须问后端,不能用 UI 语言自带的正则引擎
- **知识**:浏览器 RegExp 支持前后瞻,Rust 的 regex crate 不支持。拿前端引擎校验会放过一条「存得下、却永远不命中」的正则,**两边都不报错**,用户只看到「设了没反应」。做法:blur 时先向后端 validate,非法就红框 + 不落盘。
- **Compose / Avalonia**:同理 —— 若 Go 核心用 `regexp`(RE2,不支持前后瞻),而 Kotlin/.NET 的正则支持,则**必须**走核心层校验。这条在新栈上只会更危险。
- **出处**:`ui/desktop/pages/SettingsPage.tsx:346`、`ui/shared/api.ts:1052`

#### A-45 数据源表单**只有一份实现**,三处共用
- **知识**:添加服务器页 / 首次登录闸口 / 重新登录,共用同一份表单定义(状态、提交逻辑、字段渲染全收在一处),页面只负责摆版式:选源用什么控件(左侧 nav / 顶部芯片)、按钮叫什么、放哪儿。
- **为什么**:「这个仓库的高发病就是两处只改一处」—— 新增一个源类型时改了添加页、漏了登录页,新用户就永远看不到那个源,**而且两边都不会报错**。
- **Compose**:一个 `SourceFormState` + `sealed interface SourceKind` 驱动字段列表,页面只挑 layout。
- **Avalonia**:一个 `SourceFormViewModel`,两个 View 绑同一个 VM。
- **出处**:`ui/desktop/pages/sources/sourceForms.tsx:30`、`ui/mobile/components/SourceForm.tsx:19`

#### A-46 「服务器名称」是所有源类型的必填项,而且排**第一行**
- **知识**:每一种会建账号的源都要有它(不只是有地址的那几种:插件源的账号标识是 base_url、SMB 是主机地址,同样会把地址摆到界面上)。位置在**地址之上**、表单第一行。
- **为什么**:① 不填的话显示名回落成 host —— 侧栏、服务器页、切换菜单里到处都是真实地址,截个图发出去就把自己的服务器暴露了;② 列表里认服务器靠的就是这个名字,六台里三台叫「未命名」时,长按菜单点错的代价是**删错服务器**;③ 排第一行是因为**扫码型的用户扫完就跳走了**,放后面等于没有。
- **★ 陷阱**:后端的 login / source_login **都不收 name**,名字只能加完之后补一刀改名;手机端曾漏了这一刀,表现是「名称填了、进去显示的是地址」。改名失败**不能**把「已经加成功」变成「报错了」。
- **出处**:`ui/desktop/pages/sources/sourceForms.tsx:562`、`ui/mobile/components/SourceForm.tsx:223`、`ui/mobile/components/SourceForm.tsx:596`

#### A-47 「测试连接」只探测,不添加
- **知识**:测试连接走独立的 test_connection —— 不 upsert 账号、不落盘、不切活跃会话。
- **为什么**:以前调的是 login(),它会把账号加进去还把会话切过去,然后只回一句「连接成功」—— **用户根本没说要加**。
- **出处**:`ui/desktop/pages/sources/sourceForms.tsx:329`

#### A-48 深链解析出来 ≠ 可以直接添加
- **知识**:`linplayer://add-server` 可能来自任意网页/聊天窗。必须弹确认框把服务器地址和用户名摆给用户看,他点头才添加。
- **为什么**:直接静默添加 = 任意网页能把用户钉到攻击者的服务器上。
- **出处**:`ui/desktop/pages/sources/sourceForms.tsx:291`、`ui/shared/api.ts:1268`

#### A-49 小屏上源类型选择要分两步,不要一屏铺 13 种
- **知识**:第一步选大类(Emby / 网盘 / 局域网 / …,顺序按点开这页时的命中率排),第二步选细分。「批量」不进大类列表 —— **它是工具不是源类型**,收进右上角。
- **为什么**:上一版一屏铺 13 个格子,在 390px 屏上是三排,选完还要往下滚一屏才看得见第一个输入框,而那些格子全程占着版面。
- **出处**:`ui/mobile/components/SourceForm.tsx:142`、`ui/mobile/components/SourceForm.tsx:148`

#### A-50 没做的功能就说没做,别假装
- **知识**:摄像头扫码(需宿主相机权限+解码器)、短信验证码下发(后端还没提到命令层)—— UI 里**明说做不了**,并把可用的那条路(粘贴载荷 / 密码登录)放在下面。
- **出处**:`ui/mobile/components/SourceForm.tsx:576`、`ui/mobile/components/SourceForm.tsx:448`

#### A-51 扫码轮询:2 秒一次,过期就停,离页必停
- **知识**:2s 而不是 500ms —— 扫码是人的动作,轮询再密也快不过手速,只是白耗流量和电。离页/切换登录方式必须停,否则弹窗关了它还在后台每 2s 打上游。
- **出处**:`ui/mobile/components/SourceForm.tsx:355`、`ui/desktop/pages/sources/sourceForms.tsx:412`

#### A-52 扫码拿到的凭据**原样**落库,别拆开重组
- **知识**:各家的字段名不一样,拆错就是「扫了但没登上」。
- **出处**:`ui/mobile/components/SourceForm.tsx:370`

#### A-53 「重新登录」不填地址,只换凭据
- **知识**:重新登录拿账号当前生效的那条线路去认证,只换 token/账号;名称/备注/图标/线路/生效线路一律不动。**不要用 login() 代替** —— login 按「登录时用的地址」upsert,而这里认证走的是线路地址(≠ 账号主键),会凭空多出一台服务器。
- **出处**:`ui/shared/api.ts:599`

#### A-54 「进不进得了门」看的是有没有活跃账号,不是有没有 Emby 会话
- **知识**:登录闸口的判据必须同时看「Emby 会话」和「活跃文件浏览型源」两个。只判前者的话,只连了网盘/局域网源/插件源的用户**永远被挡在门外,加一次挡一次**。
- **出处**:`ui/desktop/App.tsx:1538`、`ui/shared/api.ts:590`

#### A-55 屏蔽类功能必须配一个集中解除的清单
- **知识**:被屏蔽的内容按设计会从首页/搜索/播放记录里消失 —— 那么**唯一能解除它的地方就只剩「原来那张卡片」**,而那张卡片也不见了。所以设置里必须有一页能一次看全并逐条解除。
- **为什么**:用户 2026-08-02 屏蔽完两个媒体库后直接问「那我怎么恢复呢?」—— 那一问就是答案。
- **配套**:媒体库网格**故意不过滤**已屏蔽的库,否则那也成了单向门;两份列表要用**不同的缓存键**(共用一个键的话,先进媒体库页再回首页会拿到带屏蔽项的那份)。
- **出处**:`ui/desktop/pages/SettingsPage.tsx:2443`、`ui/shared/api.ts:609`、`ui/shared/api.ts:1509`

#### A-56 软件把东西放哪了,要摆出来给用户看
- **知识**:设置里有一页专门列数据目录,并且要区分 `正常(便携,exe 同级)` / `被环境变量指定` / `系统回落(异常:exe 目录写不进去,数据没留在包里)`—— 最后一种 UI 必须告警。
- **为什么**:用户 2026-07-17 原话「我不知道你放哪里了,我不希望软件乱拉」。重构前数据散在 6 个根,而 UI 里一个字都没提过 —— **路径不摆出来,再干净的目录结构用户也不知道**。
- **出处**:`ui/desktop/pages/SettingsPage.tsx:2436`、`ui/shared/api.ts:1985`

#### A-57 CF 优选的粒度是**线路**,不是服务器
- **知识**:开关挂在线路上,同一台服的其它线路不受影响;标题必须带线路名(同一台服可能有多条线各开各的优选,只写服务器名会出现两行长得一模一样)。
- **为什么**:用户 2026-08-01 原话「服务器有很多条线路,而且有些线路并没有使用 Cloudflare」。按服务器开的旧口径会把该服所有线路劫持到同一个反代,而反代上游是开启时那条线定死的 —— **切到非 CF 线路后连得上、拉不到数据、还不报错**。
- **出处**:`ui/desktop/pages/SettingsPage.tsx:1519`、`ui/desktop/pages/SettingsPage.tsx:1722`、`ui/shared/api.ts:1361`

#### A-58 「预加载」和「多线程加载」是两个功能,必须分成两栏
- **知识**:预加载 = 播放**前**(进详情页)把头 N MB + 尾 2MB 跑热,读完即丢,不改播放地址;多线程加载 = 播放**中**在本地起代理超前拉 Range 喂播放器,数据落环形缓存。两者可同时开,管的是起播的两个不同阶段。用户 2026-08-01 专门点名过它们不一样。
- **出处**:`ui/desktop/pages/SettingsPage.tsx:1854`、`ui/shared/api.ts:1385`

#### A-59 会「改完要重启」的设置项必须当场说清楚
- **知识**:自定义 mpv 配置是纯文本编辑器(直接交给 libmpv 解析,我们不写 ini 解析器)。两件必须如实说的事:① 配置在播放器构造时读,而播放器是进程启动时建的 → **改完要重启应用**;② 配置里的同名选项会盖掉我们的默认值,写坏了真能让播放起不来(起不来时错误里要点名这个文件)。
- **出处**:`ui/desktop/pages/SettingsPage.tsx:666`、`ui/shared/api.ts:1430`

#### A-60 服务器卡片只显示 图标 / 名称 / 备注
- **知识**:名字下面那行小字是**备注**,不是域名、不是线路。
- **出处**:`ui/tv/pages/ServersPage.tsx:18`(承接 A-29「任何地方不展示线路地址」)

### 2.5 搜索 `ui/desktop/components/SearchOverlay.tsx`

| | |
|---|---|
| **展示** | 输入框 + 两个开关(**包括集** / **聚合跨服**)+ 搜索历史(≤8 条)+ 结果(聚合时**按服务器分组**) |
| **何时加载** | 输入防抖后打**服务端** search。旧写法是「拉全部媒体库 → 逐个全量拉条目 → 本地 includes 过滤」,每敲一次键就把整个库拉一遍 |
| **失败** | 半失败(一路 429、一路回空)不能吞成「没搜到」——见 A-4 |
| **空态** | 无 query → 显示历史;有 query 无结果 → 「没搜到」 |

**三条互相纠缠但结论明确的开关规则**(全部来自 2026-07-15 的真实反馈)
1. **「包括集」默认关**:搜「凡人」应该先看到那部剧,而不是被 200 集分集淹掉。
2. **「包括集」一拨就重搜**;**「聚合」一拨不重搜**。理由不同:聚合一次要打 N 台服务器,用户来回拨两下就是 2N 个请求(原话:「聚合搜索 我点开又关闭 会自行搜索 这是不对的」);而「包括集」只多打一次当前服,**不重搜才是坏的**。
3. **库内搜索和聚合互斥**:聚合是「跨全部服务器」,库内是「只在本服的这个库里」,是反义词 —— 有搜索范围时聚合开关**整个不出现**,别让用户拨一个必然会打破范围的开关。
- **搜索结果只有一个操作:点 = 进详情,不从这里起播**(2026-07-15 定)。
- **跨服结果不给右键/长按菜单** —— 收藏/标已看是对**当前活跃服务器**写的,对着别的服的条目按下去会写到错误的地方,而且不报错。聚合结果只能「点=进详情」,由宿主负责先切服再开。
- **类型必须显式传**:不传时服务端默认包含分集,那就是「永远包括集」;而且有的服务端带搜索词时会忽略类型参数,所以核心层还要自己再滤一遍 —— 这个开关才能在**任何一台服**上都是真的。
- 历史只在**用户真的点开了某个结果**时才记 —— 跟着防抖记的话,打「阿凡达」会把「阿」「阿凡」「阿凡达」全记进去。存坏了要逐项校验,坏了当空,别让它把浮层搞崩;写失败(隐私模式/配额满)不打扰用户。
- 出处:`ui/desktop/components/SearchOverlay.tsx:11`、`:14`、`:20`、`:37`、`:47`、`:52`、`:65`、`:104`、`:112`、`:136`

### 2.6 服务器页 `ui/desktop/pages/ServersPage.tsx`

| | |
|---|---|
| **展示** | 服务器卡网格:**图标 / 名称 / 备注 / 类型徽标 / 连通状态点 /「当前」角标**。支持搜索过滤 + 拖动排序。右键 → 编辑 / 重新登录 / 服务器线路 / 删除 |

- **备注/图标/线路/排序全部落核心层,不存本地** —— 换台机器就没了不说,核心层本来就持久化,影子存储纯属重复。(`ui/desktop/pages/ServersPage.tsx:30`)

## 3. 性能经验

> 一句话总纲:**「不秒加载」几乎从来不是动画的锅,是加载结构的锅。**
> 用户 2026-07-15 当面纠正过一次:「其实不秒加载并不是你的动画问题」——
> 我曾量到「入场动画 380ms + 按下标最多 288ms 阶梯 = 最后一张卡 668ms」就把动画砍了,
> 那是**拿掉表象**;真因是 `Promise.all` 屏障 + 串行 await,那是**秒级**的,668ms 只是零头。
> (`ui/desktop/components/Poster.tsx:82`)

**P-1 两种加载屏障,都要拆**(A 类,跟框架无关)
- **`Promise.all` 屏障**:五个各自独立的区块等齐才渲染 → 最慢的那个决定首屏。改成各自 `then` 各自渲染。
- **串行 await 循环**:`for (v of libs) await listLatest(v)` = 八个库八次串行往返。改成一次性并发。
- 新栈落法:每个区块一个独立的加载状态(`Loading / Loaded / Failed`),**页面不持有一个全局 loading**。
- 出处:`ui/desktop/pages/HomePage.tsx:199`

**P-2 骨架先出,内容各自到位**
- 用户 2026-07-16 原话:「先加载骨架出来,名字这种文字先出来,图片有加载动画看起来不会这么卡」。
- 图片未就位时是**骨架**不是空白 —— 原来 `<img>` 未加载时那块是纯空白,快速下滑一片白,看着像页面没加载出来。
- **内容出现不能被动效挡着**:入场动画 380ms 且延迟期间完全不可见,再叠 300ms 阶梯 = 最后一张卡 680ms 才出来。列表项**不挂阶梯延迟**。
- 出处:`ui/desktop/components/Poster.tsx:51`、`ui/desktop/pages/LibraryPage.tsx:326`

**P-3 屏外不解码、不排版;长列表全量渲染是可行的**
- 服务器图标网格 1468 个格子**不封顶**,靠「图片懒加载 + 屏外不渲染」扛住(用户 2026-07-16:「做成懒加载不得了」)。
- 新栈落法:Compose 用 `LazyVerticalGrid`,Avalonia 用虚拟化面板 —— 这条在原生栈上本来就是默认能力,**不要**因为「以前封顶 300」就在新 UI 里也封顶。
- 出处:`ui/desktop/pages/ServersPage.tsx:896`

**P-4 跟手的东西每帧绕过声明式层直接写变换**
- 侧滑返回 / 拖拽 / 播放器手势 / 下拉刷新:跟手期间每帧都要改位移。走状态更新的话每帧一次重组,安卓上直接掉到 30fps。**跟手期间直接写变换,松手后把最终值交回状态**。
- 「这不是猜的」—— 桌面端进度条就是这么栽的。
- **Compose**:跟手期间用 `Animatable` / `graphicsLayer{}` 的 lambda 读值(跳过重组),松手后再 `setState`。
- **Avalonia**:同理走 `RenderTransform` 直改,不走绑定往返。
- 出处:`ui/mobile/app/motion.ts:1`

**P-5 弹幕层的三条硬性能约束**(见 §1.5)
- 设备像素比**封顶 2**:弹幕是每帧全屏重画的一层,4K 屏上像素比常是 2.5~3,不封顶就是按 3 倍分辨率画,**贵一倍多**;文字本来带描边,2 倍已看不出锯齿。(`ui/shared/Danmaku.tsx:56`)
- **暂停整帧跳过**:时间不动 = 画面不会变,连清屏都省。(`:67`)
- **轨道分配 O(轨道数)不是 O(轨道数 × 在屏条数)**:弹幕一密就是这里在掉帧。(`:122`)
- 每帧的在屏列表用**原地压缩**而不是新建数组 —— 每秒 60 次、弹幕密时上百个元素的热路径。(`:139` 附近)

**P-6 缓存的三条口径**(细节见 §4)
- **详情缓存只做内存 TTL 5 分钟,不落盘**:里面带续播进度/收藏/已看,这些随时会变、还会被别的设备改;落盘跨重启复用 = 重开 App 看到上次的旧进度 —— **那不是省流量,是给自己造一个「进度莫名回退」的 bug**。图片按 tag 基本不可变,才该落盘。(`ui/shared/api.ts:682`)
- **列表也要缓存,尤其为了返回键**:TV 上返回键是主交互,每次退回首页都要重跑「媒体库 + 继续观看 + 接下来看 + N×最新」,机顶盒网络下就是用户说的「每次打开都要更新」。(`ui/shared/api.ts:709`)
- **随机推荐也要缓存**:它每次返回不同条目,不缓存就意味着每次退回首页都要重新下载 5 张大图 —— 这是 TV 上「每次打开都要更新」最刺眼的一处。5 分钟内保持同一批,过期自然换新,随机性没丢。(`ui/shared/api.ts:907`)

**P-7 同一面板里的多个请求必须并发**
- 字幕翻译面板四个调用串行 await,把后端本身的卡**放大了四倍**(用户 2026-07-15 报「每次打开设置的字幕翻译每次都会卡」)。后端是元凶,但串行是放大器。
- 出处:`ui/desktop/pages/SettingsPage.tsx:1109`

**P-8 分页拉分集,别全量拉**
- 实测最长那部剧 2648 集:全量 1813.9KB / 1841ms,分页 30 条 20.0KB / 435ms。
- 出处:`ui/shared/api.ts:788`

**P-9 悬停触发的请求必须有缓存,而且「查过=没有」要能表示**
- 鼠标在几档之间来回扫会反复触发,每次重发就是「一扫就闪一下」。缓存里**存 null 表示「查过了,确实没有」**,不能用「键不存在」表示,否则没内容的那条每次展开都会再查一遍(反复打空)。
- 出处:`ui/desktop/pages/CalendarPage.tsx:557`

## 4. `api.ts` 命令桥里值得带走的设计

> `ui/shared/api.ts`(2037 行)是三套前端调核心层的**唯一入口**。
> 它本身是 C 类(Tauri invoke 的类型化封装,新栈里换成 FFI/本地 HTTP 就没了),
> 但里面有六条设计是 **A 类**,换栈后仍然要有人做这些事 —— 只是换个地方做。

### 4.1 「唯一入口」这件事本身就是设计
- **知识**:所有页面走这一层,不散落裸调用,改一处全端生效。
- **为什么**:下面 4.2~4.6 每一条,都是因为有这一层才做得成。散落在页面里,每一条都得靠各调用点自觉。
- **新栈落法**:Go 核心的对外面(FFI 导出表 / 本地 HTTP 路由)是同一个位置;三套原生 UI 各有一层薄客户端,但**跨端一致的逻辑(缓存、失效、广播、URL 拼装)必须在 Go 侧,不许每端抄一份**。
- **出处**:`ui/shared/api.ts:3`

### 4.2 让「改数据」这个动作本身成为信号 —— 变更广播
- **知识**:维护一张「会改动账号表的命令名」清单,在**调用层**拦截:凡是命中的,调用成功后自动广播一次变更事件。
- **为什么**:真源在核心层,而前端每个页面各持一份副本,副本之间没有任何连接。**「改完记得通知别人」是靠人记的**,而这正是 2026-07-15 那个 bug 的成因:服务器页改名称/备注/图标/密码走的是「不通知外层」的回调,侧栏于是永远显示旧名字。
- **★ 维护要求**:新增会改账号表的命令时要把名字加进清单 —— **漏加 = 侧栏又不刷新,且不报错**。
- **新栈落法**:这条在新栈上**更容易也更该做** —— Go 核心自己知道哪次调用改了账号表,直接从核心层推事件,连清单都不用维护。这是「换架构能真正消灭掉一个 bug 类」的少数例子之一。
- **出处**:`ui/shared/api.ts:13`

### 4.3 缓存失效表:整体清,不定点清
- **知识**:维护一张「会改条目状态的命令名」清单,命中就**整体清空**详情缓存和列表缓存。
- **为什么(第一版按 itemId 定点清是错的)**:
  - 标记分集已看,变的是**剧集**的 `children[].played`。定点清分集 → 剧集详情还是旧的 → 用户点了「已看」,列表纹丝不动,且不报错。
  - 进度上报的参数里**压根没有条目 id**,定点清是个永远删不掉东西的空操作。
  - 这些都是低频用户动作(收藏/标记/停止播放),整体清最多让几个详情重取一次,换来的是「不可能因为漏清而显示旧状态」。
- **★ 例外**:高频的进度上报**不进清单**,进度由停止播放时收尾清一次就够。
- **出处**:`ui/shared/api.ts:697`、`ui/shared/api.ts:709`

### 4.4 切服务器 / 切线路 / 重登 = 必须清详情缓存
- **知识**:条目 id 在不同服务器上**可以重复**。不清就会拿 A 服的详情去画 B 服的条目,**而且不报错**。
- **出处**:`ui/shared/api.ts:42`、`ui/shared/api.ts:750`

### 4.5 缓存键必须编进全部入参,而且「形状不同的同名数据」要分池
- **知识**:① 包 TTL 缓存时,key 必须把全部入参编进去,否则不同参数会互相串;② **形状不同的数据不能共池** —— 「带分集的详情」和「不带分集的详情」共用一个池,先进后者的话前者会莫名少了整个分集列表;③ 「滤掉已屏蔽的媒体库列表」和「全量媒体库列表」也必须两个键,共用一个键的表现是「屏蔽了但回首页又出来了,再刷新才没」。
- **出处**:`ui/shared/api.ts:718`、`ui/shared/api.ts:807`、`ui/shared/api.ts:609`

### 4.6 图片 URL 由核心层拼,前端只给条目 id
- **知识**:图片走自定义协议 → 字节由核心层给,命中磁盘缓存(2GB / 30 天),miss 才回源。**两个变化都别退回去**:
  1. **URL 里不再有 token**。以前是 `?api_key=…` 直接进 `<img src>` —— token 就摊在 DOM 里、网络日志里、服务端 access log 里。
  2. **不再依赖会话里的服务器地址**。换线路不会让缓存整盘失效(核心层用账号主键当缓存键)。
- **★ 反例警告**:图片 URL 的拼法**只能有一处**。路径白名单在核心层,散在页面里的拼法会绕开它。
- **新栈落法**:Compose 用 Coil / Avalonia 用自定义 `IImageLoader`,统一指向核心层暴露的图片端点;**绝不在 UI 层拼上游地址**。
- **出处**:`ui/shared/api.ts:1883`、`ui/shared/api.ts:1964`

### 4.7 「命令归哪个平台」要在源码里标出来,而且这个标记是**契约**
- **知识**:只有安卓壳注册的那几条命令用成对的区块标记圈起来。**两端的契约测试都按它切分** —— 桌面那条「每个调用都注册过」跳过本区块,安卓那条**只查**本区块。
- **为什么**:少了它,要么桌面 CI 因为查不到这几条而红(2026-07-21 那次),要么把区块整个豁免掉、这几条从此没人把门。
- **新栈落法**:Go 核心里按 build tag / 接口分平台,并**保留这条「跨端命令表必须被测试覆盖」的纪律**。同源的另一条:源类型的线上字符串有一条 Rust 侧跨语言契约测试钉着前端的联合类型 —— 前端曾整套写成首字母大写,导致每处比较恒 false、登录送错值,**两边都不报错**。
- **出处**:`ui/shared/api.ts:1849`、`ui/shared/api.ts:356`

### 4.8 参数形状要诚实:只收真正会改的字段
- **知识**:选轨偏好的写入只收三项 —— 核心层也只认这三个。以前标成「整个偏好对象」,逼调用方拼一个完整对象再扔掉多余字段:**看着像「整体覆盖」,给人一种「不传的字段会被清掉」的错觉**,新增字段时每个调用点都得跟着改一遍。
- **反向的坑**:如果核心层**真的是**整体覆写(三项一起写),那调用方就**必须先取基线再改单项** —— 否则选个音轨顺手把字幕语言偏好抹了,两头都不报错。
- **出处**:`ui/shared/api.ts:1048`、`ui/desktop/pages/DetailPage.tsx:380`

## 7. 存疑

> 判定方法在 §0。下面这些**我没能干净地分进 A/B/C**,或者出处不足以下结论。
> 按红线:**不写「应该/可能/大概」,读不出来就写「未确认」并说明查过哪里。**

### 7.1 分类分不清的

**Q-1 「独立播放窗口」是产品决定还是桌面平台产物?**
- 事实:桌面端播放页是**第二个窗口**,用户 2026-08-01 再次点名要的。它带来一串配套约定(退播放=隐藏不销毁、Alt+F4 要拦、进全屏前必须先退最大化、播放窗不受登录闸口管辖)。
- 分不清的点:「用户要的是独立窗口」是 A 类;但「隐藏不销毁因为重开一次 WebView 要几百毫秒」这个理由在 Compose Desktop / Avalonia 上是否还成立,**未确认** —— 我没有新栈上的窗口创建耗时数据。
- 出处:`ui/desktop/App.tsx:230`、`:899`、`:934`

**Q-2 弹幕显示参数「归渲染侧」这个划分,换栈后还成不成立?**
- 事实:当前划分是「速度/字号/不透明度/显示区域/开关 = 渲染参数,核心层用不到」(`ui/desktop/App.tsx:151`)。
- 分不清的点:新栈里弹幕渲染**要搬进核心层**(§1.5 的前提),那这五项就变成核心层要读的数据了 —— 那条「不该往核心层加自己永远不读的字段」的理由会反转。**这个划分需要在新栈上重新做一次决定**,别照搬。

**Q-3 三端 OSD 版式差异,哪些是「端的差异」哪些是「历史包袱」?**
- 事实:手机端 OSD 是用户定的九宫格(A-22);桌面端是自绘窗口控制 + 九个面板(A-34);TV 端另有一套。
- 分不清的点:桌面端**是否也该用九宫格**,仓库里没有任何一条注释讨论过。**未确认**(查了 `ui/desktop/App.tsx` 的播放层注释和 `docs/desktop-drafts.html` 的存在性,没找到相关论证)。

**Q-4 `ui/mobile/app/motion.ts`(747 行)的动效原语,有多少要带走?**
- 事实:它整段来自 `docs/mobile-drafts/motion.js`(87 格评审台逐格看过的原型),零依赖,只动位移和不透明度。里面的 Material 规格数字(涟漪 600ms linear、scale 0→2)是**产品规格**(A 类);实现手段全是 DOM 操作(C 类)。
- 分不清的点:M3 的 emphasized 缓动曲线**不是三次贝塞尔**,当前是用分段线性逼近的。Compose 有官方的 M3 motion token,直接用即可;**Avalonia 上用什么** —— 未确认。
- 出处:`ui/mobile/app/motion.ts:1`、`:54`
