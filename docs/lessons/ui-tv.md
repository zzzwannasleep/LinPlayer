# TV 端 UI / 焦点

**这个领域最容易踩的坑:**
1. **焦点问题在静态稿和截图上完全看不出来**,必须真按遥控器/派发真按键,并断言「焦点项是否完全在视口内」。
2. **容器不能设 `focusable:false`**(焦点进不去)、`layoutAdapter` 必须开(我们的焦点态带 scale)、焦点项不能贴裁剪边。
3. **按↓原地不动多半不是没重叠,是重叠过头**:负 margin 把行矩形撑高 32px,候选被直接删掉。
4. **输入 = 焦点框本身就是输入框**,包一层 div 的话 Android 输入法永远不升起。
5. **TV 的交互密度不能照搬 PC**:鼠标点击代价与距离无关,遥控器代价 = 焦点格数。

### TV 端 UI 选型

> 原记忆:`tv-ui-stack-decision.md` · 类型:`project`

**2026-07-20 定**。TV 端 UI 从零起版，落在 `ui/tv/`（原先只有 README 占位）。
产品形态**对齐 PC 侧栏 8 项**（搜索/首页/媒体库/收藏/下载/排行榜/日历 + 服务器/设置），
不用 `git show rust-final:docs/TV_DESIGN.md` 里那份 Flutter 时代的 4 项导航 —— 那是产品还没长出来时定的，
该文档的**视觉/交互决策仍可参考，实现路径（Flutter/Riverpod/GoRouter/tvOS）全部作废**。

##### 焦点库：@noriginmedia/norigin-spatial-navigation

用户 2026-07-20 拍板"直接一步到位"，不走"先裸跑 WebView 原生焦点、不够再加库"的渐进路线。

| 配置 | 值 | 为什么 |
|---|---|---|
| `useGetBoundingClientRect` | **true，强制** | 官方要求：元素带 CSS transform/scale 时必开。**我们的焦点态就是 `scale(1.12)`** —— 不开则库拿到变换前的矩形，方向判定算错邻居 |
| `throttle` | 120ms + `throttleKeypresses:true` | 遥控器长按方向键会疯狂重复，不节流会冲到列表尽头且掉帧 |
| `setKeyMap()` | **上真机 log 完 keyCode 再填** | 各厂商 D-pad keyCode 不统一（标准 37-40，部分 TV 用 400-403），别写死 |
| `shouldFocusDOMNode` | true | 让库调 `HTMLElement.focus()` —— ⚠️ **只 focus 登记的那个节点**，救不了包在里面的 `<input>`，详见下方坑 5 |
| `saveLastFocusedChild` | 默认 true，**别关** | 焦点丢失（掉到 body → 遥控器彻底失灵）是 TV 最经典 P0，靠它 + `autoRestoreFocus` 解决，**别自己写焦点记忆** |
| `isFocusBoundary`+`trackChildren` | 面板/对话框 | 必须配 `FocusContext.Provider`，只写 isFocusBoundary 不生效 |

**库不管的两件事**（[仓库结构(2026-07重构后)](build-release.md) 里 `apps/android` 仍待建，这两条通道要先落）：
`KEYCODE_BACK` 被 Activity 吃掉、媒体键同理，都得从 `onKeyDown` emit 给前端。**壳里不预留，整个 TV 端后期改不动。**

##### 真机前置:命令层还锁在桌面宿主里(2026-07-20 落码时发现)

**225 个 `#[tauri::command]` 全部定义在 `apps/desktop/src/lib.rs`**(5000+ 行,桌面专属),
`crates/core` 一个 tauri 依赖都没有(**故意的**,为了交叉编译安卓)。
于是 `apps/android` 建起来之前,**TV UI 在真机上一个命令都调不到** —— UI 做完也上不了机。
把命令层从桌面宿主里抽出来是一件独立的、不小的活,不在"照草稿落 UI"范围内,但它是上真机的前置条件。

当前开发/验证路径因此是:**跑桌面 Tauri 壳,让它加载 `index-tv.html`**(vite 多入口,
`index.html`=桌面 / `index-tv.html`=TV),拿到真实 Emby 数据 + 真实 mpv。

**跨服版本聚合有硬上限**:`aggregate_search` 跨服但**不带 MediaSources**
(`emby.rs::search_url` 的 Fields 里没有),`item_media` 只打当前服,
`set_active_server` 会 `cfg.save()` 改全局会话不能当探测手段。
所以别台 Emby 的版本卡只能如实标「规格未知」并置灰,**不许编分辨率和码率**。
要出完整四层信息,核层必须加一个「按 serverId 查条目 MediaSource」的命令。

##### 落码阶段实测踩到的四个坑(2026-07-20,都不是看文档能避开的)

**这四条全部是「静态稿 / 截图上完全看不出来」的**,只有真按遥控器才暴露 —— 见文末验证手法。

1. **容器不能设 `focusable: false`**(P0,焦点根本进不去)。
   库的 `smartNavigate` 只在「同一 parent 下 **focusable** 的兄弟」里找目标。
   我把 `FocusRow`/`FocusColumn`/`Rail` 都设成 `focusable:false`(想着"容器又不是焦点目标"),
   结果它们从候选里被整个剔掉 → **按↓完全不动,焦点永远进不了任何一行**。
   容器保持默认 true,落上去时库会自己往下钻到子项(lastFocusedChild / preferredChild)。

2. **`useGetBoundingClientRect: true` 在 3.2.1 已 deprecated**,换 `layoutAdapter: GetBoundingClientRectAdapter`
   (内部就是转成它)。但**必须开**这件事不变:默认适配器读不到 CSS transform 和 zoom,我们两样都用。

3. **gBCR 是缩放后的设备 px,`style.transform` 是未缩放的 CSS px** —— 混着用滚动距离只有该走的 `zoom` 倍
   (实测 0.61 → 焦点项永远差一点点露不全,比完全不滚更难发现)。
   写回 transform 前必须 `delta / zoom`。库自己不受影响:它全程 gBCR,同一坐标系比大小。

4. **库没有 `onChildFocused`,也没有 `onBackPress`**(我两个都凭印象写了,都不存在)。
   官方滚动模式是「父把 `onFocus` 回调传给子」;返回键得自己从壳的键桥接。
   ⚠️ 嵌套时子项只能看见**最近的**那个滚动容器 —— 行套在列里,行必须把通知**往上冒**,
   否则行内左右滚得好好的、整行却永远不进视野。

5. **`shouldFocusDOMNode` 救不了输入框 —— 电视上根本打不出字**(2026-07-21,P0)。
   库只 focus **登记的那个节点** = `FocusItem` 的包装 `<div>`。那个 div 没有 `tabIndex`,
   `.focus()` 是 no-op,`document.activeElement` 全程停在 `<body>`。
   **Android 输入法只认 DOM 焦点**,所以系统键盘永远不升起,按 OK 毫无反应。
   必须**手工把 DOM 焦点转交给里面的 `<input>`**,并且 `pause()` 空间导航
   (否则方向键既移光标又移虚拟焦点 —— 光标不动,焦点先飞走),Enter/Escape 时 blur+`resume()`。
   ★ 教训不止于此:这个桥接原先散在 SearchPage / SettingsPage 各写一遍,
     **首次启动的加服务器页漏了 → 装上根本没法登录**。已下沉进 `FocusItem`
     (子树里有 input 且未给 onEnter 时自动接管),给了 onEnter 的调用方走自己的,零回归。
     「每个调用点各自小心」这种设计,漏的那个一定是最要命的那个。
   ⚠️ 当时 `OnboardingPage` 里还写着「shouldFocusDOMNode 让输入法升起」的注释 ——
     **注释描述的是代码没做到的事**,同款陷阱见 [「待接」多半是谎](methodology.md)。
   ⚠️ **2026-07-21 这套两段式被用户否掉,已整体删除**(见下一条)。

6. **输入:焦点框必须就是输入框**(2026-07-21 用户原话:「你选中的框和输入框可以分开的?这是为何」)。
   坑 5 那套"先选中 → 按 OK 进输入态 → `pause()` 全局导航 → Enter/Esc 退出"能打出字,
   但把**选中和输入做成了两件事**:高亮画在外层 div、里面才是 input(看着两个盒子);
   进输入态后上下键失效,**想先填密码再填地址得先退出再走位** = 顺序被隐式钉死。
   现版 `FocusInput`(`ui/tv/components/Focus.tsx`):**登记进焦点树的就是 `<input>` 本身**,
   焦点到即 DOM focus(IME 自动升起,不用按 OK),上下键照常换字段;
   左右/Backspace/Home/End 在 input 上 `stopPropagation` 截住给光标用
   —— 截得住是因为**库在 window 的冒泡阶段监听 keydown**(核对过 dist 源码)。
   `FocusItem` 里的 input 桥接已随之删干净,全站 `<input>` 只剩 `FocusInput` 一处。
   ★ 首次登录页初始焦点**故意停在"连接"按钮**上:焦点一落输入框 IME 就升起盖住半屏,
     而那一页的主路径是扫码。

##### 手机控制台(扫码遥控,2026-07-21)

用户原话:「扫码就不应该只做这个登录功能……这个网页可以当遥控器使用操控软件」。
**电视没摄像头,只能"电视出码、手机扫"**(这一点用户一度以为我做反了,其实一开始就是对的;
但我把它做小成了一次性登录表单,那才是真错)。

- `crates/core/src/companion.rs` + `companion.html`:tokio TcpListener 手写极简 HTTP,
  **只管传输**,业务靠宿主注入的 `Handler = Fn(接口名, JSON) -> JSON`。core 不认识 tauri。
- `apps/android/src/lib.rs::companion_call`:接口名 → 直接调**同一批 `#[tauri::command]` 函数**。
  能这么做的关键是 **`AppHandle::state::<T>()` 在命令之外也拿得到同一个 `State`** ——
  不必把业务抄第二份(抄了就一定分叉:手机改的设置和电视改的走两套代码)。
- 手机页能做:遥控盘/播放控制(进度条+快进快退+停)/跨服搜索并让电视打开/服务器增删切/
  设置(主题·语言·字幕·代理·清缓存)。**默认开机即起**(`AppConfig.companion_enabled`),
  设置页「网络 → 手机遥控」有开关和二维码,首启页也有。
- **遥控按键不能在 Rust 里"执行"**:要落到 WebView 的焦点库上。所以 Rust 只 `emit`,
  `ui/tv/app/remote.ts` 合成 KeyboardEvent。两个硬点:
  1. **keyCode 是只读的**,构造参数里给了不生效,必须 `Object.defineProperty` 塞
     (Edge 无头实测:不塞 = `keyCode 0`,焦点库直接忽略);
  2. 派发目标是 **`document.activeElement`** 而不是 window —— 输入框拿着焦点时
     左右键要移光标,派到 window 就绕过输入框了(实测事件照样冒到 window,焦点库收得到)。
- **手机改了账号表必须 `emit("lp://accounts-changed")`**:那条广播平时是前端 invoke 层发的,
  手机走 Rust 直连,电视一无所知 → 首启时手机登录成功、电视还停在"添加服务器"那一屏。
  切服务器(含搜索结果跨服打开)同理,否则页面揣着上一台的 session 副本画新服条目。
- 片名靠前端 `set_now_playing` 报给核层(mpv 的 Status 里只有时间没有片名),播放页离开时清空。
- 与 `config_transfer.rs` 的 `LPSYNC1:` **不是一回事** —— 那个是"把已有账号搬到另一台",
  需要对面有摄像头,电视做不了。

**另:卡片焦点态草稿里一次都没画过**(22 屏里 `.foc` 只出现在按钮/面板项/chip/列表行上)。
实现时才发现环套整张卡会紧贴标题文字底边;改成**环画在封面 `.th` 上**(也是 TV 通行做法)。
这条属于「草稿没覆盖到的情况」,不是抬升时抄漏。

##### 其它硬约束

- **mpv 走 SurfaceView 垫在透明 WebView 之下** —— 桌面那套"两个顶层窗口对齐"不能照抄（见 [重构决策(已定+PoC已验)](decisions.md)）。
- **禁 backdrop-filter / 大 blur / 动画 box-shadow**：机顶盒 WebView 很弱。PC 端也栽过（[本周看板定案+PC视觉自检](methodology.md)）。
- **10-foot ≠ 什么都放大**（用户 2026-07-20 纠正我的错误假设）：
  1920 屏在 **3 米外的视角大小和笔记本在臂展距离差不多**，要放大的只是「必须读的字」，不是所有元素。
  **Hero / 详情页上封面才是主角，控件让位**：标题 36–40sp（不是 52–56）、按钮 52dp / 17sp（不是 64dp / 20sp）、
  信息块最宽 600dp。做大只会把封面糊死，反而丢掉这一屏最该给的信息。
  （列表项、正文、按钮文字该大还是要大 —— 区别在于「要读的」和「只是布局元素」。）
- **不用渐变，只有两种状态**（用户 2026-07-20 连着两次否掉渐变后立的规则）：
  压在画面/封面上的东西 **要么全透明，要么不透明块**。全屏渐变每帧都要重新合成，
  机顶盒上是笔冤枉开销，而且渐变边界远看是糊的。
  - 播放页：上下栏**全透明**（无任何底色），进度条 / 时间 / 按钮**全不透明**，统一 `--tv-panel`，与侧面板同色。
  - 首页 Hero、详情页：**文字直接落在封面上**，不画渐变也不画半透明底。
  - ⚠️ **连带必须做的**：裸文字（播放页标题、时间）失去渐变兜底后会糊在亮场景上，
    所以它们要**自带不透明底**；按钮（`.btn`）也一律不透明 —— 半透明白在亮画面上淡到看不见。
    某处真读不了时，解法是给那块文字一个不透明底，**不是加回渐变**。
- 全局 `@media (hover:hover)` 包住 hover 样式 —— WebView 在 D-pad 移动时会误触发 hover。
- 过扫描安全区 48/64dp；焦点放大的行要留 20dp 呼吸位，否则光晕被祖先 `overflow` 裁掉。
- 强制深色，不加载 `tokens.css` 的浅色分支。

##### 草稿维护:截图自检 ≠ 结构自检（2026-07-20 翻车实录）

**一路吃穿了 04、05、06 三整页**（播放页本来就没 rail，没有锚点拦住它）。

##### 产品口径（用户 2026-07-20 逐条纠正，都是我照搬 PC 造成的）

- **「线路」只出现在线路管理页**。媒体库标题下、播放页 OSD 副标题、服务器卡片，
  一律不显示线路或 URL。详情页的版本面板选的是 **MediaSource（版本）**，不是线路 —— 两个概念别混。
  播放失败页也不内联「换线路」，跳去线路管理做。
- **服务器卡片名字下面那行小字 = 备注**（如"客厅常用"），不是域名、不是线路。
- **首页 Hero 不打「随机推荐」标签**，也不放继续观看（下面已有整行）。
- **TV 的交互密度不能照搬 PC**：鼠标点击代价与距离无关，遥控器代价 = 焦点格数。
  横排 6 个筛选 chip 在 PC 免费，在 TV 是「5 次方向键」→ 改成单入口 + 右侧面板。

##### 源范围与版本选择（用户 2026-07-20 定）

- **TV 端只做四种源**：Emby / 飞牛影视 / 网盘 / OpenList。**不做 Ani-RSS 订阅**
  （要填 RSS 地址和正则，遥控器上是灾难，留给手机和 PC 端）。
- **剧详情页不出现版本 / 音轨 / 字幕选择** —— 剧的层级上没有"版本"，每集片源可能来自不同来源。
  全部下放到**集详情页**。电影没有"集"这一层，版本行留在电影详情页，**但用同一套版本卡组件**。
- **版本行只聚合 Emby 服务器**（用户 2026-07-20 定）。网盘 / OpenList / 飞牛**没有 MediaSource 这个概念**，
  要聚合就得逐个探测文件是否存在 —— 为一行选择器做这件事不划算。
- **版本卡不显示观看进度**：起播一律接当前进度，不管这个版本在别的服务器上看到哪。
- **集详情页底部是「集数栏」，不是上一集/下一集按钮**。两个按钮一次只能挪一格，
  24 集的番要按 18 次。集数栏**紧跟版本行**（别用 `margin-top:auto` 贴底，会显得突兀）。
- **选集栏做成可切换的两种视图**（用户 2026-07-20：「做一个切换按钮不得了，A/B 都能选」）：
  | 视图 | 形态 | 一屏 | 跳到第 24 集 | 适合 |
  |---|---|---|---|---|
  | 紧凑（默认） | 集号 chip，选中恒居中，两端渐隐 | 13 集 | ~11 次 | 长番、已在追的剧 |
  | 详细 | 285×263dp 卡：封面+集号+标题+时长+两行简介 | 5.4 集 | ~19 次 | 短剧、第一次看 |
  **切到详细时顶部简介必须自动隐藏** —— 卡片自带简介，否则同一段话一屏出现两次。选择要持久化。
  ⚠️ 详细视图的两行简介只能给 15sp + 三级墨色，**三米外基本读不了**，这是它的隐性弱点。
- **不做「登录 / 切换用户」页**；**服务器页只显示 图标 / 名称 / 备注**三样，
  媒体库数量不外显（对"我要用哪台"这个决定毫无帮助）。
- **图标按钮必须带文字**（用户看到裸图标方块直接问"那是什么"）。全站一套 24 视野 stroke 线性图标，
  草稿里**绝不留空方块占位** —— 评审时"这个按钮干嘛的"必须一眼可答。
  播放控制左组（上一集/快退/播放/快进/下一集）是通用约定可纯图标，
  右组（字幕/音轨/弹幕/更多）必须图标+文字。
- **模式 ≠ 新页面**：服务器排序模式与服务器页**共用同一张卡、同一栅格、同一间距**，
  只叠虚线框 + 顶部提示带。两个模式画成两套版式，用户会以为进错页了。
  （我曾把排序模式画成另一套窄卡，用户当场指出。）
- **面板照搬 PC 的 `.p-slide` 形态**（`ui/desktop/theme/player.css`，注释里已写明它当初就是从
  「贴右满高一整列」改成「悬浮在右侧中部的圆角区块」的）：TV 版 **460×820dp，右侧居中悬浮，
  距右 64dp，圆角 20，不铺满高度**，视频画面大部分露在外面。**没有黑色遮罩**；
  面板打开时 **OSD 自动收起**。
  ⚠️ 唯一不照抄 PC 的：PC 用 `backdrop-filter: blur(12px)`，**机顶盒开毛玻璃掉帧，TV 用不透明底 + 阴影**。
- **不自建虚拟键盘** —— Android TV 有系统输入法（Leanback IME），输入框聚焦按确认即升起，
  还白拿语音输入和外接键盘。自建只会更难用，还得自己维护中文候选。
  但**系统键盘会盖住下半屏**，所以要输入的内容和历史必须放上半屏。
- **搜索页版式**：左栏 560dp = 搜索框 + 历史（常驻，**标题右侧带「清空」按钮**，别藏进菜单键）；
  右栏 1016dp = 范围 chip → 结果（chip 紧贴结果上沿）。聚合时**结果行尾标来源服务器，同片多台不去重**。
- 草稿支持 **1:1 全屏预览**（点任意一屏，ESC 退出）。默认 `scale(.554)` 判断不了远距离可读性，
  而那正是 TV 设计的成败点。Tauri 用 WebView，草稿 CSS 与最终代码同源，浏览器所见即真机布局。

- 集详情页版本卡 380×212dp，信息四层且字号拉开：
  | 层 | 字段 | 字号 | 为什么 |
  |---|---|---|---|
  | 1 | 来源（色块+名）+「当前」标 | 18sp | 用户要知道从哪台播 |
  | 2 | **分辨率** | **30sp** | 三米外唯一一眼可辨的字段 |
  | 3 | 编码 · **码率** · 体积 | 17sp | 只给 4K/1080p 分不出好坏：4 Mbps 的 2160p 不如 15 Mbps 的 1080p |
  | 4 | 音轨 · 字幕语言 | 16sp | 次要，选定版本后进面板细挑 |
- 排序 = **当前来源 → 分辨率降序 → 码率降序**，焦点默认第一张；播放按钮上写明将用哪个版本起播。
- **必须异步回填**：当前来源本地已有数据立即显示，其它来源回来一个填一个。
  等齐再渲染 = 进页白屏两秒。复用 [跨服请求生命周期](network.md) 的聚合口径。
- **不可用来源保留但不可聚焦**（消失会让用户以为片源丢了，占焦点位又浪费按键）。
- ⚠️ **跨来源"同一集"靠 系列名+季+集号 认定，而系列名有服务端会缺失** ——
  置信度不足的卡片必须打「可能匹配」黄标，不能默认匹配正确。

另两条用户当场纠正的：
- **草稿里绝不能写真实服务器域名和内网 IP**，属泄露。一律 `media.example.net` / `192.168.x.x` / `服务器 A/B/C`。
- **TV 的交互密度不能照搬 PC**：鼠标点击代价与距离无关，遥控器代价 = 焦点格数。
  横排 6 个筛选 chip 在 PC 是免费的，在 TV 是「5 次方向键」。已立成草稿里的「TV ≠ PC」规则节。

##### 验证手法:必须真按遥控器,截图不算数

上面四个坑**没有一个能靠截图发现**(截图里焦点环好好地待在第一张卡上,一切正常)。
可用的办法是 [挂真机 CDP 调试](methodology.md):

1. `npm run dev` 起 vite,再 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222 ./target/debug/app.exe`
2. CDP `Page.navigate` 到 `http://localhost:1420/index-tv.html` —— **拿到的是真实 Emby 数据 + 真实 mpv**
3. `Input.dispatchKeyEvent` 连打方向键,每步 dump `document.querySelectorAll('.foc')` 的文本
4. 断言不是"有没有焦点",而是**焦点项是否完全在视口内**(`rect.top>=0 && rect.bottom<=innerHeight`)——
   坑 3 正是靠这条抓出来的:焦点一直在,只是永远露不全

⚠️ **中文结果一律写 UTF-8 文件再读,不要 print 到控制台** —— Windows 控制台 GBK 会把
「华语剧集 / 外语剧集」糊成同一串字节,我因此把 12 个不同的媒体库读成了"行重复的 bug",
差点去改一个根本不存在的问题。同类见 [PowerShell GBK/UTF-8 坑](build-release.md)。

**Why:** TV 端最容易翻车的不是审美是焦点，而焦点问题在静态稿上完全看不出来，必须提前把库的约束写死。
**How to apply:** 按草稿末尾的五批评审顺序推进（外壳+首页 → 播放页+面板 → 媒体库+详情 → 搜索+加服务器 → 其余）。
画稿必须[本周看板定案+PC视觉自检](methodology.md) 无头 Edge 渲染自检 —— 这次四轮抓到 5 个肉眼在代码里看不出的 bug（键盘溢出 130dp 是算出来的，不是看出来的）。

### 焦点按↓原地不动

> 原记忆:`norigin-rect-inflation-kills-candidates.md` · 类型:`project`

norigin 方向导航筛候选的条件是「兄弟的上边 ≥ 自己的下边」。
**重叠 = 直接从候选集里删掉，不是排序靠后。** 所以症状是**按↓完全不动**，而不是"跳错地方"。

坑在 `tv.css` 的 `.hscroll { padding: 32px 0; margin: -32px 0 }`（为了不裁焦点环）：
这对 padding/负 margin 会**穿过 FocusRow 的外层 div 合并**，让整行登记给库的矩形
**上下各比视觉多 32px**。于是任何跟在横向行前面、间距 < 32px 的那一栏，
按↓时下面那行已经"盖住"了自己 → 被筛没 → 死胡同。

⇒ **紧跟 `.hscroll` 行的元素，下边距必须 > 32px**（40 是安全值）。
2026-07-21 一次修了三处：季度 chip 22→40、按钮行 34→44、选集表头 14→40、版本行 30→40。

绕不开的一种：角距太近。集详情页「详细」按钮右边缘与版本行右边缘只差 4px，
库的斜向惩罚（5 倍）也压不过 → 焦点被吸到右上角小按钮。**这种只能显式跳转**：
capture 阶段拦键（库在 window 冒泡监听，capture 先到）+ `setFocus(FK)`。

认「当前焦点项」不能用 `document.activeElement`（焦点项是普通 div）。
用 **`[data-focused]`**：库在 `focusNode` 里 `setAttribute('data-focused','true')`
（blur 时移除，需 `shouldFocusDOMNode: true`，本项目 focus.ts:53 已开）。
⚠️ 这个属性在 `@noriginmedia/norigin-spatial-navigation/dist` 里**搜不到** ——
那三个文件只是 re-export 壳，真身在 `-core` / `-react` 子包，别据此断定"库没这功能"。

另一类相关但不同的病：**滚动只保证焦点项自己露出来** → 往上回到 Hero 时停在按钮顶端，
上面 400+px 封面在视野外（表现为「内容缺失/回不到最顶」）。
解法在 `ui/tv/app/scroll.ts`：往上按**段顶**对齐（段 = `.inner` 的直接子元素），
第一段贴到真顶；往下仍按焦点项底（段可能比整屏高，按段会翻过头）。

相关：[TV 端 UI 选型](ui-tv.md)、[测试必须先红](methodology.md)
