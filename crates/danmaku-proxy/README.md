# LinPlayer 弹幕代理

把弹弹Play 的签名从客户端挪到服务器,顺带自己存一份弹幕。

**为什么要有它**:客户端里的 AppSecret 无论怎么加密都是可提取的 —— 解密口令必须和密文
一起发出去。谁拿到安装包都能用你的配额,客户端限流拦不住外人。挪到服务端之后:

- 密钥只在这台机器的环境变量里,客户端一个字节都拿不到;
- **出站闸门**把「收到多少」和「转发多少」解耦。被刷爆的后果退化成「这段时间弹幕慢」,
  配额一个不掉;
- **自托管弹幕库**按 cid 求并集长期留着。一百个人看同一集,上游只打一次;
  而且**配额烧光的时候仍然有弹幕可发**,不是回一个错误。

---

## 一、部署

服务只监听回环地址,前面挂你自己的反代 + Cloudflare。它**不做** TLS、不做 IP 封禁、
不做 DDoS 防护 —— 那三件事反代和 CF 做得更好。

### Docker(推荐,服务器上不用装 Rust)

在**仓库根目录**执行:

```bash
docker build -f crates/danmaku-proxy/Dockerfile -t linplayer-danmaku-proxy .

docker run -d --name danmaku-proxy --restart unless-stopped \
  -p 127.0.0.1:8787:8787 \
  -v /srv/danmaku-proxy:/data \
  -e DANDANPLAY_APP_ID='你的AppId' \
  -e DANDANPLAY_APP_SECRET='你的AppSecret' \
  -e ADMIN_PASSWORD='一个够长的管理密码' \
  linplayer-danmaku-proxy
```

`-p 127.0.0.1:8787:8787` 里的 `127.0.0.1:` **不要去掉** —— 去掉就等于把一个没有 TLS
的服务直接挂到公网上。

`/data` 里装着弹幕库,**必须持久化**。它会长到几个 G(上限在管理界面里调)。

> 凭据别写进 `docker-compose.yml` 再提交 —— 用 `--env-file`(文件加进 `.gitignore`)
> 或 docker secret。这份 README 里也一个真值都没有,照着填。

### 不用 Docker

```bash
cargo build --release -p linplayer-danmaku-proxy
# 产物:target/release/linplayer-danmaku-proxy(单文件,无运行时依赖)
```

systemd 单元见本目录 `linplayer-danmaku-proxy.service`。

### 反代(OpenResty / nginx)

只需要一段 location:

```nginx
location / {
    proxy_pass         http://127.0.0.1:8787;
    proxy_set_header   Host              $host;
    proxy_set_header   X-Real-IP         $remote_addr;
    proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
    # 单集弹幕能到几 MB,默认的 proxy_buffer 会频繁落临时文件
    proxy_buffering    off;
    proxy_read_timeout 30s;
}
```

### Cloudflare(橙云)

**没有客户端令牌** —— 拦人这件事整个交给 CF。所以这几条规则不是可选的:

| 规则 | 目的 |
|---|---|
| Rate limiting:`/api/v2/*` 每 IP 每分钟 60 次 | 主力。挡单机猛刷,而且挡在源站之前 |
| WAF:`/admin*` 只放行你自己的 IP(或加 Access) | 管理界面能改闸门、清空整个弹幕库 |
| Cache Rules:**不要**缓存 `/api/*` | 我们自己已经缓存了,CF 再缓一层只会让"刚更新的弹幕不出现" |
| Bot Fight Mode | 挡掉最没成本的那批扫描 |

真被打爆了,最坏的结果也只是这个域名不可用 —— **弹弹配额一分不掉**,因为出站闸门在
源站这一侧,CF 挡不住的请求到了这里也过不了闸门。

**国内可达性**:你之前实测过「国内 CF 有地方阻断、GitHub 反而稳」(插件仓库因此没挪 CF)。
上线前先拿这个域名实测一轮。真不通的话,留一个直连源站的备用域名,客户端两条都试。

## 二、环境变量

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `DANDANPLAY_APP_ID` | ✅ | — | 弹弹Play AppId |
| `DANDANPLAY_APP_SECRET` | ✅ | — | AppSecret。**多串轮换密钥**可换行分隔,服务只取第一串 |
| `ADMIN_PASSWORD` | ✅ | — | 管理界面密码,至少 8 位。没有默认密码,不设就拒绝启动 |
| `PORT` | | `8787` | 监听端口 |
| `BIND` | | `127.0.0.1` | 监听地址。容器里由镜像设成 `0.0.0.0` |
| `DATA_DIR` | | `./data` | 配置、弹幕库、缓存都在这里。**要持久化** |
| `UPSTREAM_BASE` | | 弹弹官方 | 只给自检用(拿假上游顶替,免得跑一次测试烧一次配额) |

其余所有旋钮都在管理界面里改,**改完立刻生效不用重启**(缓存磁盘上限除外)。

## 三、弹幕库怎么工作的

弹幕**不走**普通缓存,它有自己的一套:

- **只增不减**。每次从上游拉回来按 `cid` 求并集。上游哪天返回残缺数据(实测过回空列表)
  也毁不掉历史 —— 我们是最后一份拷贝,替换的写法会把用户这一集的弹幕永久清零。
- **惰性刷新**。只在有人真的请求这一集、而且距上次拉取超过了间隔时,才去上游看看。
- **间隔自适应**,在你设的下限(默认 6 小时)和上限(默认 7 天)之间走:
  - 一次刷新长了新弹幕 → 说明还在播/还在被看 → 压回下限;
  - 一条新的都没有 → 翻倍,直到上限。

  在播的番自然停在 6 小时,老番自然滑到 7 天。这么做而不是去查「哪部是当季新番」:
  少一条上游依赖、少一个会过时的判断,而且**老番突然翻红也跟得上** —— 按季度判断
  永远判不出这种情况。
- **上游挂了回存量**。闸门关着或上游 429 时,过期的那一份照发不误(响应头标 `STALE`),
  而不是把错误甩给用户。这是自己存相对每次问上游最实在的收益。

响应头 `X-LP-Cache` 能看出走了哪条路,线上排障直接看它:

| 值 | 含义 |
|---|---|
| `FRESH` | 库里还新鲜,一次上游都没发 |
| `UPDATED` | 去上游拉了,而且拿到了新弹幕 |
| `NOCHANGE` | 拉了,但一条新的都没长(间隔据此翻倍) |
| `STALE` | 过期了但上游拿不到,发的是存量 |
| `HIT` / `MISS` | 搜索/集表/排行榜走的短期缓存 |

## 四、上线后第一件事

打开 `https://你的域名/admin`,把**出站:每天上限**改成你在弹弹那边真实配额的 80%。

默认值(3000/天)只保证「不会一天之内烧光」,不保证用满 —— 它不知道你的配额是多少。

顶上八张卡分别是:已存弹幕集数(及其中还新鲜的)、弹幕总条数、弹幕库占用、今日上游调用、
本分钟上游调用、短期缓存命中率、短期缓存占用、被出站闸门拦下。

跑几天后该长这样:

- **已存集数**稳步上升,其中「还新鲜」的占大头 —— 这些请求一次上游都不发;
- **今日上游调用**远低于播放次数。如果它贴着上限跑,要么用户涨了,要么有人在刷,
  看「用量最高的来源」那张表;
- 那张表按**真正花掉的上游次数**排,不是按请求数 —— 一直命中弹幕库的重度用户一次配额
  都没花,要抓的是穿透上游的那个。看见谁不对劲,去 CF 上封。

> ⚠️ 被 Cloudflare 挡掉的请求**不会**出现在这张表里(它们根本没到源站)。
> 那部分看 CF 自己的分析面板。程序只看得见到达了源站的流量。

## 五、接口

客户端直接打,**不需要任何凭据**:

```
ANY /api/v2/<弹弹的路径>   → 弹弹的响应原样透传
```

白名单只放行 `search/anime`、`search/episodes`、`bangumi/`、`comment/`、`match`、
`trending/` —— 不做通配转发,那等于给全世界开了一个带我们签名的免费代理。

**错误口径**照弹弹自己的来:HTTP 200 + body 里的 `errorCode`,客户端已有的解析器
直接就能显示。自定义码:

| 码 | 含义 |
|---|---|
| 1001 | 服务被管理员关了 |
| 1002 | 单来源限流 |
| 1003 | **出站闸门拦下** —— 上游配额今天用完了 |
| 1004 | 上游不可达 |
| 1005 | 不在白名单的接口 |

## 六、排障

| 现象 | 先查 |
|---|---|
| 启动就退出,`[致命] 需要…` | 三个必填环境变量少了哪个 |
| 全部返回 `errorCode:1003` | 出站闸门已用满。管理界面看「今日上游调用」,UTC 00:00 重置 |
| 上游一律 403 | 签名错。最常见的成因是 AppSecret 是**多串轮换密钥**而被整坨拿去签了 —— 本服务已处理(只取第一串),但如果你在别处也用这个密钥,注意同样的坑 |
| 弹幕不更新 | 看 `X-LP-Cache`。一直 `FRESH` 说明还在间隔内 —— 调小「刷新间隔下限」,**改完对存量条目立刻生效**,不用等 |
| 一直 `NOCHANGE` | 上游确实没有新弹幕了。间隔会自己翻倍到上限,这是正常的 |
| 磁盘一直涨 | 弹幕库上限调小,后台每 5 分钟按「最久没人看」淘汰一次 |

自检:

```bash
cargo test -p linplayer-danmaku-proxy          # 27 条单测
node crates/danmaku-proxy/e2e.mjs              # 端到端(自带假上游,不碰真配额;约 20 秒)
```
